# 家属主账号手机号保护

迁移 `mysql/0031_family_phone_protection.sql` 为 `family` 增加 AEAD 密文、HMAC 精确索引及保护标记。启用服务密钥后，管理员建立的待激活家属、邀请码注册和资料改号都在原业务事务内写入新列，并清空 `family_phone`。原接口字段、权限范围、家属与老人绑定及密码规则保持不变。未启用保护的部署仍可读写显式标记为未保护的旧记录。

密文按 `account-phone:family:<family_id>` 认证；其他家属或管理员账号不能复用。手机号查询沿用 `account-phone` HMAC 域，保留管理员/家属跨角色冲突检查。两类账号共用不可替换的 lookupKey 指纹；任一角色已有保护记录时，缺失密钥、指纹丢失或不匹配都会拒绝查询/写入，不自动重建绑定。错误 scope、密文损坏、明文与密文并存或标记不一致均返回错误，不回退为“未找到”。

登录、家属资料、老人详情、评论作者头像查找和公告/照护通知均使用同一保护逻辑。授权 API 仍返回手机号，通知仍按既有收件人 scope 单独加密入队；这不意味着授权界面不再可见手机号。

## 历史回填

1. 部署并确认 0031 迁移成功，停止所有账号写实例、旧服务和相关 worker，建立可核对的停写屏障。先在隔离环境验证含旧 key/lookupKey 的备份能够恢复。命令本身不会建立这些保障。
2. 在后端目录构建 `go build -o protect-family-phones ./cmd/protect-family-phones`。使用受限文件配置 `MYSQL_DSN_FILE`；默认运行只读扫描，不需要读取加密密钥，不打印手机号或索引。
3. 使用与服务一致的 `DATA_ENCRYPTION_KEY_FILE`，执行 `protect-family-phones --apply --limit 100`。允许范围 1–1000，单次最多运行两分钟。它先验证指纹和全部已保护家属密文，再逐行锁定未迁移记录，验证合法性及跨角色唯一性，独立事务提交。原 lookupKey 必须保留，不能顺便切换查询密钥。
4. 查看 stdout 聚合 JSON 的 `pending_before`、`migrated`、`remaining`、`complete`。限额到达但有残留时返回非零、`complete=false`；保留屏障并重复执行。中途遇到非法旧手机号/冲突会停止，先前已提交行保留。按实际业务核实并修正问题后可恢复；未完成最终计数时 `remaining=null`，不能解释为零。
5. 确认 `family_phone_protected=false AND family_phone IS NOT NULL` 为零，验证登录、改号、家属权限、通知及恢复演练后才恢复写入。重复执行不会重写已经认证通过的密文。扫描模式的退出零仅代表扫描成功，不代表已经完成迁移。

已有密文纳入 [rekey-data](../reliability/rekey-data.md) 的第 22 项，轮换保留 HMAC、指纹和账号状态。回填与重封装都不会清除备份、binlog、副本或对象中的历史副本，不授权删除旧 reader。

## 回退与剩余范围

0031 回退脚本保留扩展列、索引及迁移记录，不将密文自动降级为明文。旧二进制不能读取已保护家属记录；业务回退必须使用能读取当前格式的应用，或按已演练方案恢复相匹配的应用、数据库和密钥。不能仅回滚程序或删除保护列。

本次仅保护 `family` 主账号手机号。社交 `said.said_phone`、`nice_count.phone` 等历史/新写副本、老人/监护人电话、姓名、地址、健康 JSON 和历史备份仍需独立设计迁移，不宣称全库或全部联系方式已加密。

真实 MySQL 测试覆盖回填预检/部分提交/恢复/幂等/仅新 reader 登录、命令的受限配置文件与部分完成返回、两种通知收件人及注册到资料改号的 HTTP 流程，另有角色/行隔离测试。四个数据库测试列入必需结果审计，缺失、失败或意外跳过均阻断门禁；这些测试不替代真实生产停写及灾难恢复验收。
