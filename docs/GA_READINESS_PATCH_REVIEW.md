# v2.1.0 GA-readiness 补丁评审与适配记录

来源：`suining-v2.1.0-ga-readiness-patch.zip`，原始说明称基于
`smart-elderly-watch-management-2.1.0-20261122.zip`。
本次以 GitHub `preview` 分支提交 `4aefaa46508afe70f1f8b1864f7cd23afa229b76`
作为适配基线，**没有直接解压覆盖仓库**。

## 评审结论

- 原始补丁关于 “100% 向后兼容”“除硬件外全部 GA 就绪” 的声明没有配套
  完整回归和真实数据迁移/恢复证据，不能据此认定正式发布可用。
- `config.Secret()` / `*_FILE` 和响应 `BaseResponse` 已在基线存在。
  本次只扩展配置域，复用现有密钥读取，不重复实现。
- 原始 `SITE_TZ_OFFSET_HOURS` 定义为 `int`，会丢失半小时/四分之一小时
  时区表达能力；适配为 `float64`、校验 -12..14，非法或非有限值回退到 8。
- 原始 Rust 签名测试使用了无效的 `b"{"a":1}"` 字符串语法；
  已改为合法 raw byte string，并保留签名一致性/载荷变化测试。
- 原始 `protect-notes` 虽加入 `LIMIT`，但在无索引的备注条件上
  `SELECT ... FOR UPDATE` 可能锁住大量扫描记录。适配为**先无锁有界候选扫描，
  再按主键逐条加锁、检查值没有变化、同表事务提交**。每次最多
  1000 条/表；无匹配索引时数据库仍可能扫描很多行，不能称为恒定耗时。
- `goccy/go-json` 在当前 `backend/go.mod` 中已存在；仅调整响应路径，
  保留 JSON 字段名称、错误码及序列化失败时的安全 500 兜底。
- 现有 `protect-*` 命令路径和 `--apply`/`--limit` 参数不变，
  新增 `suining-ctl protect <target>` 六种统一入口，复用相同
  回填函数和输出报告。仅这六种已统一，`protect-notes` 和
  `protect-user-phones` 仍是独立命令。

## 运行与验收

普通开发者应只执行变更涉及的单元、类型、静态检查和构建，遵从
仓库选择性 CI 方案（另见 PR #204）；这份补丁自身修改了后端、前端和
模拟器，关联测试不可跳过。正式发布另需完整来源 SHA 的构建证据。

针对旧数据回填：
1. 在测试环境验证备份恢复和原始密钥/密钥环。
2. 暂停对应业务写入，先不带 `--apply` 做预览。
3. 以 `--limit 100` 或更小批量显式执行，观察锁等待和剩余数量；
   必要时多次运行。出现错误立即停止并核对数据库。
4. 不要把 `protect-notes` 输出的 `candidates` 当作全表待处理总数，
   它表示**本次最多 `limit` 条候选**。
