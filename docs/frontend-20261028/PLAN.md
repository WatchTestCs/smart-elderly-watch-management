## 执行顺序及停止条件

1. G0：核对版本、当前检查与模块边界；本计划先于依赖/业务修改落盘。
2. G1：干净 npm ci、npm ls、单测、类型检查、构建、审计；保存命令、退出码、锁文件哈希、环境。盘点所有 workflow 与 QA，区分 mock、真实后端、浏览器与原生。
3. T00：生产构建资源 raw/gzip/Brotli；固定合成数据、1440×1000，冷/暖缓存各至少 5 次首屏与关键交互；图表开关 20 轮，在固定点记录实例、监听器及内存。只报告探索性基线，不据此认定性能收益。
4. G1-V：核实官方 Vue 发布和 npm 包元数据及 peer/engine；在隔离目录仅变更 Vue 精确版本，执行不带 force/legacy-peer-deps 的包管理器解析和干净安装。先解决实际依赖约束，不通过 overrides 隐藏混装。
5. 迁移只有兼容性、适用回归、可归因收益和回退均有证据才放行；出现真实 peer 阻塞、未解决回归或无收益证据时，保存失败原文，恢复基线依赖，T08 保留受阻/待验收。T01/02/04/05/06/07 可继续盘点和故障复现，不越过 G1-V 推进依赖实现。
6. G2/G3：只有 G1-V 通过才按模块实施；每项独立可回退，先登记收益、门槛、边界及验证方式。T03 的缺失检查随对应改动接入。
7. G4/G5：核对最终差异与证据，更新任务登记表、覆盖矩阵、桌面交接文档，给出 M01–M08 判定。未运行项目如实标记；部分完成不记作全部完成。新分支提交/推送后核对真实远端状态。

## 实验与收益预登记

| 项目 | 修改前问题/假设 | 主指标与最低实用门槛 | 非回退边界与方法 |
| --- | --- | --- | --- |
| T00 | 当前 SHA 缺本机可复现基线 | 记录资源、首屏、健康图表交互与固定点内存原始数据；探索样本≥5，图表20轮 | 不修改业务数据；mock 明示；工具失败不计样本，保留失败证据 |
| T08 兼容预检 | Vue 3.6 RC 可能不满足现有稳定 peer 范围 | 不使用强制选项的正常解析、实际树一致、干净安装锁文件稳定 | 现有依赖不因仅支持未来版本而无依据全量升级；先查官方精确元数据 |
| T08 项目收益候选 | 仅升级不构成收益；尚未发现项目内确定修复或必需新能力 | 若无确定正确性/能力收益，性能候选为本项目健康页图表开关的操作到完成耗时：预期中位数至少减少10ms且≥5%；同时资源累计不得增加>5% | 最终性能论证须双批、每版≥20独立样本、A/A、A/B/B/A、配对差95%CI全在改善方向；预检失败不开始性能收益实验，不用微基准替代 |
| T02 只复现 | 活动 read 永不返回时，最新 read 排队且 dispose 不取消 | 三次确定性复现：新 read 不被调用、loading 无终态、dispose 不终结 Promise；并保留正常乱序用例结果 | 不修改业务实现；不将机制复现写成线上用户故障 |

原生 WebView2 必须实际运行应用场景，检测到运行时已安装不等于通过。缺环境/自动化不记成功。任何性能收益门槛不得在看到候选结果后更改。

基线测量方法修正（仍在比较候选之前）：现有 QA harness 使用 Playwright routing，会禁用 HTTP cache，因此不能提供真正冷/暖资源缓存对照。该批保留为 pilot，不作缓存证据。最终基线使用独立 HTTP 合成响应服务器，不使用 routing；明确测试服务器 HTML/API `no-store`、静态资源 `max-age=3600`、文本 gzip 的固定口径。此策略用于可重复测试，不代表线上 Go/nginx 实际配置；真实后端另行验收。地图测量点击到本地 Leaflet 标记可见，在线瓦片失败/授权行为沿用现有 QA，网络供应商时延不混入基线。
