# 岁宁 2.0.5 · 值守、权限与隐私验收门槛

## 版本性质

本版在 2.0.4 的持久化 SOS、通知发送队列、人工处置、复核和独立服务部署基础上，增加**进程心跳监测、岗位权限、敏感请求审计、任务下一步提示**。此版是源码预览，不得视为真实生命安全保障系统已验收。

## 1. 通知可靠性与全天候运行

- **部署**：机构运行 Go 后端应使用 `deploy/suining-care.service` 等独立常驻进程；不应把随桌面程序关闭的附属服务当作唯一 SOS 接收端。
- **状态区分**：`received` 仅代表入库；`pending/failed` 是队列状态；`sent` 只代表网关已接受；`delivered` 必须由可信网关签名回执确认；`acknowledged` 才是工作人员接手。
- **持久化与重试**：通知保存在 `care_notification_outbox`，异常退出后 `sending` 任务可重领；网关必须按照 `Idempotency-Key` 去重。
- **心跳**：`care_worker_heartbeat` 每轮更新。工作台超过 30 秒未见心跳会显示高优先级提示。仅有心跳不保证渠道送达，也不保证每个实例都正常。
- **故障演练**：分别测试数据库断开后恢复、服务进程强制终止与重启、网关 429/5xx/超时、发送成功后网络中断、重复回执、SOS 重复 requestId、无人接单与处置超时。
- **应急预案**：心跳中断、告警积压或通知无人送达必须有值班人员可执行的**线下人工救助路径**。软件故障不应阻止直接拨打当地急救电话。

## 2. 工作台任务优先

- 首页优先展示未复核任务、老人、设备、责任人、通知进度、处理期限与下一步动作。
- 超时任务突出显示。任务发生、通知送达、接单、登记处置、二次复核保持独立。
- 限制仅看到前 50 条任务这一事实：这不是无限长度的完整值守队列；真实运行中须按机构容量扩展分页、搜索和监控。
- 维持原绿色视觉设计，检验移动/桌面端响应式与低视力辅助功能。

## 3. 岗位权限

- 账号认证基础角色仍是 ADMIN / FAMILY。FAMILY 不得访问照护管理端点。
- 主管（supervisor）可查看诊断、分配岗位、复核和查看审计；护理员（caregiver）仅可接单、开始及登记处置，不能独立复核；审计员（auditor）只读照护任务和履历。
- 兼容既有数据：没有单独设置岗位的 ADMIN 暂按 supervisor 处理。**上线前必须盘点所有旧 ADMIN 账号，完成最小权限岗位分配。** 此兼容策略本身不是完整最小权限治理。
- 当前岗位规则**只对照护业务接口进行细分**；原有 ADMIN 其他管理接口仍是管理员通用权限。2.0.5 不宣称已经具备连锁机构多租户隔离或全系统 RBAC。

## 4. 隐私与审计

- `care_access_audit` 记录照护任务查看、履历查看、主管操作与岗位调整。
- `care_sensitive_access_audit` 对已认证用户访问老年人、健康、位置、家属、设备等路由写审计，**失败则拒绝放行**；不保存请求正文、坐标值或手机号。
- 审计记录尚无自动保留期限管理、加密密钥轮换、按院区隔离和不可篡改外部归档；应依据部署地区法律与机构规则制定保留与删除策略，禁止将“已留痕”视为全部合规。
- 真实交付应补充：数据脱敏导出、备份恢复、权限更改回滚、人工审计抽查、撤销员工权限时会话行为和访问记录归档。

## 5. 发版检查与已知边界

自动检查：Go test/race/build/vet/gofmt、PostgreSQL 迁移及集成测试、前端构建、UI Quality、Security。人工未覆盖边界包括真实手表、真实短信网关、Windows 安装包和弱网硬件全链路，必须由部署方按上述情境实测。

验收指标建议：通知网关接受成功率、真实送达回执率、SOS 接单 P95、超时未处置事件、心跳丢失分钟数、恢复后通知重试与重复发送比例；不只报告在线设备数量。
