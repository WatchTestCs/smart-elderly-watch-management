# 体征异常处置输入与原因归属修复

基线：preview / f6250e7e65b3f14ba61cfeae93460591bf528609。

对照用户最新《长期工程治理、问题清单与开发交接规范》排除项，本批不处理 P0-01 至 P0-04、P1 工程化、旧技术栈、文档治理、代码拆分或 CI 建设。仅修复普通心率/血压记录处置的两个具体业务错误。

| 编号 | 优先级 | 修复前实测 | 方案 |
| --- | --- | --- | --- |
| C31 | P1 | /ratepre/resolveAlert 的 kind 为 rat、all、数字或对象时，仍返回成功，并将两类异常与处理时间一起改写 | 写入前拒绝非字符串及未知非空类型；保留现有 rate/pre、大小写处理及空/省略类型的双类处置语义 |
| C32 | P2 | /device/resolveAlert 指定较早的偏高记录，更新该记录后却返回较新偏低记录的 handledReason；心率和血压均可复现 | 原异常检索增加可选 recordID 约束；指定记录处置的原因按同一 deviceID/recordID 读取，普通详情、剩余异常检查和未指定记录处置仍读取最新异常 |

查询仍参数化，未增加新 SQL 翻译、数据层抽象、业务路由或字段。没有数据库迁移、历史数据修正、前端改造、通知状态转换或敏感数据策略变更。接口对非法类型现在返回 400 且不写入，合法输入行为保持。

两条新回归先在修复前失败：非法类型清空两类异常，以及高值目标返回低值原因。修复后 MySQL 8.0.46 的四条相关顶层用例通过，覆盖两条新回归、配置阈值原因及零值缺测。补充验证现有详情和批量处置路径后，仅复验两条新用例通过；handlers go vet、OpenAPI 生成一致性、差异检查通过。

新回归检查非法请求不改变异常状态或处理时间，合法单类处理不触碰另一类，空/省略类型仍同时处理两类；指定记录处置不影响较新记录，较新异常仍能读取，后续批量处置仍返回其正确原因。[原始输出](../../evidence/core-bugs-20261030/vitals-resolution.txt)。本地仅使用真实隔离 MySQL 测试库，未启动 PG、未重复全量、race、压测或浏览器套件；PG 现有回归由适用 CI 执行。

无数据迁移；回退应用提交即可恢复原处理逻辑，但会重新引入非法类型误处置。现有空/省略 kind 的双类处理是已保留的业务行为，本批不重新设计成新的批量 API。精确 head 的 CI、CI 后烟测与合并状态以对应 PR 和本地输出回执为准。
