# 定位页面告警快照与 SOS 坐标修复

基线：preview / 7b9766df5612d54c26c3e9f75cb21fb39b598a3d。仅处理用户商业级问题清单之外的三个具体业务缺陷。

| 编号 | 优先级 | 实测错误 | 修复方案 |
| --- | --- | --- | --- |
| C28 | P1 | 10 点告警、11 点定位时，告警弹窗展示 11 点的时间和坐标 | 定位响应分别返回最近定位与最近告警快照，弹窗读取告警自身时间和附带坐标；缺失值明确展示未知 |
| C30 | P1 | SOS 无坐标时把旧定位刷新到求助接收时间；只传经度时又与缓存纬度拼成新点 | 不从设备缓存补填 SOS 坐标：完整坐标按原流程处理，无坐标仍受理求助但不写新定位，单边坐标在写入前拒绝 |
| C29 | P2 | SOS 与摔倒共用的紧急状态被管理员、家属和概览页面统一称为已确认摔倒 | 同一状态统一展示为紧急告警；零状态展示未告警/已处理，不凭共用标志推断事件种类 |

保留既有坐标加密读取、权限、绑定版本、请求幂等、通知和处置流程。新增响应字段为 alarmTime、alarmLng、alarmLat，原有定位字段含义保持不变。查询列使用独立别名，兼容 MySQL 列表分页派生表。无迁移或历史数据改写。

两条后端新回归及三条前端用例在修复前失败。修复后 MySQL 8.0.46、PostgreSQL 17.6 各七条关键路径通过，覆盖加密坐标、管理员列表及管理员/家属详情、无 GPS 求助、半组坐标拒绝且不落库、遥测时间排序、SOS 正常坐标、过期绑定拒绝和请求幂等。前端三条定向用例及一次生产构建通过。最后删除失去用途的缓存解密后，额外仅复验无 GPS SOS 一条并执行 handlers 的 go vet。OpenAPI 生成一致性检查通过。
