# 监护人关联完整性与年龄校验修复

基线：preview / 586ae2c94f7d8577bae4c3d8091dbe7dc5d511d5。仅处理最新长期治理清单之外的档案业务错误，不进入 SOS、通知、加密迁移、生产准入、旧栈/文档治理、架构或长代码拆分。

| 编号 | 优先级 | 修复前实测 | 方案 |
| --- | --- | --- | --- |
| C33 | P1 | 老人档案接受不存在的 customerId；直接删除已关联长者的监护人后，详情关联失效 | 新建、编辑档案及删除监护人在同一事务中先锁定同一监护人行；不存在时拒绝档案写入，仍有关联时拒绝删除。两个入口计为同一项引用完整性缺陷 |
| C34 | P2 | 监护人新增/编辑接受 -1、151 岁并写库；小数和非数字返回 500 | 使用前端既有 0–150 岁整数规则，写入前返回 400；保留数值和整数字符串输入 |

原前端规则依据：frontend/src/composables/useCustomers.ts 的 validAge 及 customer.vue 的年龄提示。引用完整性依据：老人新建/编辑必选监护人，详情按 customerId 连接真实监护人资料；失效 ID 不能完成该业务关联。

档案写入先锁监护人、再锁/写长者；删除先锁监护人，再检查是否被长者引用。各入口使用同一个 parent 行协调并行请求，不靠先查存在再无锁写入。现有前端对业务失败不报告成功或移除记录。没有数据库迁移、外键建设、历史行修复或清理；这里只约束现有应用入口，不声称阻止直接 SQL 写出无效数据。

三条新回归在修复前失败，分别检出无主档案、删除关联失效和非法年龄写入/错误状态码。修复后真实隔离 MySQL 8.0.46 的八条顶层关键路径通过：三条新用例及原生日/年龄、合法新增、设备绑定保护、家属关联保护、列表/数值年龄契约。两条已有回归仅补真实监护人夹具，原断言未删改。

因引入事务协调，另补一次创建档案与删除同一监护人的同时请求：恰有一个成功，最终无悬空引用，通过。补充拒绝意外 500 的断言后，仅定向复验该用例通过。不是压力测试、重复 race 套件或所有交错证明。handlers go vet、OpenAPI 生成一致性和差异检查通过。[原始输出](../../evidence/core-bugs-20261030/guardian-integrity.txt)。未跑本地全量、PG 业务写入、前端构建或浏览器套件；适用 CI 另行校验当前 head。

API 路由、字段、权限和数据库职责不变。缺失监护人/仍关联长者时使用原业务失败包络；年龄输入错误为 400。回退应用提交即可恢复旧逻辑，无数据回滚；回退会重新允许失效引用和不合法年龄。已有失效引用不自动修正，需在正常档案编辑时选择有效监护人。
