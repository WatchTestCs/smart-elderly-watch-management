## 问题与方案

此前只隔离了经纬度与事件时间，设备声明的元数据会被忽略；新回归在原实现上失败。新增三项可选输入、两类独立快照的加密元数据与显式事件 kind；历史未知保持未知。已有 gps 默认值和 sos 触发来源都不作为定位技术来源。前端显示设备自报、未知或历史采样，不再把地图点标为“当前位置”。[完整接口契约](../../智慧养老手表管理系统/backend/docs/position-context.md)。

MySQL 新增 0020、PG 回归新增 0018；注册 MySQL 执行列表，并扩展现有回滚重放回归，确保撤销登记后重放不改写新旧快照。无历史清理、迁移历史改写、KMS 改造或通知状态机变动。回退应用时保留元数据列与数据，不以删列丢失上下文来回滚。

## 实际验证

- 旧版一条真实隔离 MySQL 回归失败，检出来源/采样/精度/类型丢失。首次实现因遗漏迁移登记返回 500，登记后通过；失败原文保留。
- MySQL 定向八条顶层关键路径通过，覆盖三条新回归、原 HTTP 告警快照、幂等、独立定位及重绑定。
- PG 现有回归环境七条顶层路径通过，包含新元数据、非法输入不落库、旧数据未知、原快照、过期绑定与事务回滚。PG 只是已有回归覆盖，不改生产主库职责。
- 扩展管理员/家属详情断言和迁移数据保留后，MySQL 迁移回滚重放、元数据、绑定拒绝和 SOS 事务回滚通过；补充重复 SOS 不改写首次元数据的断言后，仅复验对应路径。
- 前端五条定向用例、类型检查、一次生产构建通过。go vet、OpenAPI 生成一致性和差异检查通过。

原 PG 私有旧目录启动时缺少 pg_notify，因此新建另一个私有集群后验证，未修改旧数据；该启动失败不计为业务测试失败或成功。未运行本地全量、多轮 race、完整浏览器 mock、真机或生产通知验收。[原始输出](../../evidence/pr50-context-20261031/acceptance.txt)。
