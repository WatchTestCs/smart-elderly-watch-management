# 睡眠乱序与换绑位置快照修复

基线：preview / f86d5b25b6b71707dc8d1ba14cdd45ad28cbab2c。只处理用户商业清单以外的两个具体上报缺陷，不修改实验锁开关、通知升级、权限模型、审计或迁移工具体系。

## 批量发现与排序

| 编号 | 优先级 | 可复现结果 | 解决方案 |
| --- | --- | --- | --- |
| C18 | P1 | 同日先收到 10:00 的 8 小时正常睡眠，再收到 09:00 的 2 小时异常睡眠，当前值变为 2 小时异常；11:00 只报状态后，10:30 的包又覆盖状态 | 时长、状态各自保存观测时间，数据库原子比较后更新；缺失字段不推进时钟，0 时长仍有效 |

## 集中设计与实现

睡眠两个字段可独立上报，不能共用一个时间戳：11:00 的状态不应阻止 10:30 的时长更新，但必须阻止该包较旧的状态覆盖。新增 sleep_observed_at、sleep_state_observed_at，只在对应字段实际存在时写入。MySQL 与 PostgreSQL 的原生 upsert 按字段原子比较，允许同一观测时间的修正，不改变现有步数排序。

MySQL 0019、PostgreSQL 0017 仅为日表和已有归档表各补两个可空观测时间列，不变更唯一键。换绑时这两个时钟与原日快照一起归档，新绑定清空；旧记录无可信观测时间时保持 NULL，首个带时间的上报建立顺序。回退仅撤销迁移登记，保留所有列及历史数据。部署时统一升级写入端，旧写入端仍会绕过新字段的顺序判断。

位置修复只收窄设备快照更新 SQL 的比较集合，不改变定位历史、告警创建、通知发送和 SOS 状态机。
