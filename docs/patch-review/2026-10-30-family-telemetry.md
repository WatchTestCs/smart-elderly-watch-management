# 家属与设备上报定向修复

基线：preview / 5a5ad4a3ce857ff1a7428bbf930673f4d898a75b。

- 家属按手机号查询资料、修改头像和密码时，同时约束当前会话账号 ID，避免管理员改号后旧号码复用造成跨账号读写。管理员原有查询范围保留；没有重做会话系统。
- 添加家属锁定老人记录，已有绑定返回 409 并回滚新家属记录；界面显示具体失败原因。
- 管理员预建的无密码家属，可用同一老人的有效邀请码及原登记手机号首次设密。只允许激活原绑定的 NULL 密码账号，不能重置已有密码或替换家属。添加成功后界面说明该步骤。
- 日步数新增 step_observed_at，旧采样不能覆盖新值；较新的合法修正允许降低数值，不含步数的上报不推进步数时间。
- 位置查询按 be_time、id 选择，设备最近坐标也拒绝较旧定位覆盖。历史定位仍保存；位置页时间只取对应定位，不再混入告警或建档时间。

## 迁移与部署边界

MySQL 新迁移为 0017，PostgreSQL 兼容迁移为 0015。仅新增可空观测时间字段与位置索引，不改旧迁移校验和、不回填猜测的时间、不删除业务数据。遗留日步数在首次收到带步数的新上报后建立时间顺序，无法反推出已有旧值的真实观测时间。

迁移在启动路径中应用。生产部署前仍需备份并评估位置表索引构建耗时；本次未操作生产库。升级时应暂停设备写入、排空事务并统一升级写入端，旧程序不维护新增观测时间，混用期间不能保证乱序保护。回退程序时可保留新增字段与索引；对应回滚脚本只撤销迁移登记，重新应用不会丢失观测时间。

## 验证范围

仅运行五项缺陷回归、三项直接相关 SQL/缺字段兼容回归、已有邀请码竞争与绑定约束回归，以及新增迁移涉及的回滚重应用用例。数据库验证使用本地独立 MySQL 8.0.46，每项业务用例创建并清理随机测试库；静态检查仅覆盖 handlers 与 db，前端只做一次生产构建。

没有扩展全套测试、压力或混沌测试；PostgreSQL 兼容迁移与原生桌面/真实手表流程未运行验收。最终命令结果随交付说明提供。
