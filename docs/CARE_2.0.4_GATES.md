# 2.0.4 照护闭环：第一阶段安全边界

该分支目前**不是完整 2.0.4**，不得作为完整照护产品发布。

## 本阶段实际完成
- SOS 请求在原有告警入库事务中新增持久化 incident，带唯一事件 ID。
- 保存事件接收日志；数据库任一步骤失败则整笔事务回滚。
- 响应明确说明仅收到求助，未通知发送、未确认送达、未人工接手。
- 定义后续通知任务表及审计记录表（尚未启用投递消费者）。

## 完整版合并门槛
1. 为指定照护责任人持久创建 outbox 通知任务，安全异步重试，能确定失败、发送与真实送达回执；不得以短信供应商接受请求冒充送达。
2. 增加具备岗位权限的接单、处置、升级、复核接口；基于乐观并发和事件日志防重复接单、越权操作、状态回退与漏审计。
3. 对未接单 / 处理中超时使用独立常驻服务执行升级；部署健康检查与备份恢复；桌面退出不能让通知任务无声停止。
4. 首页突出待处理任务、超时和责任人，家属端有权限隔离。
5. 实际设备、短信故障、网络断开、数据库重启、并发竞争、超时及迁移回滚验收；压力与性能基准。
6. 权限、审计、个人数据最小暴露与保留策略；文档、部署脚本、版本升级和可用的 2.0.4 源码包。

未达以上条件前，不得将 received 状态写作已通知或已接单。
