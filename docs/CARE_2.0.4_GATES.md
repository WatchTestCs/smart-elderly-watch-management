# 岁宁 2.0.4 照护闭环：实现范围与正式交付门槛

## 已实现的可测试代码

- SOS 与告警事件及审计记录原子落库，返回唯一 incidentId；已移除“已通知家属”的未经验证承诺。
- 带稳定 requestId 的设备 SOS 重试使用数据库事务锁及唯一索引去重；新的求助按新的 ID 创建。
- 家属手机（若存在且格式有效）创建持久化通知 outbox。通知网关 HTTPS/令牌配置后，后台负责带幂等键异步投递、异常重试和重启后的超时认领。
- 将网关 HTTP 接收（sent）与签名确认的真实送达（delivered）区别记录；若网关没有送达回执，则不会虚构 delivered。
- 提供管理员照护任务查询、接单、开始处置、填写措施、二人复核、重新开启及逐步审计履历。家属不能操作管理端事件。
- 独立 Go 服务 worker 检查超时，生成升级事件；可配置值班升级联系电话。
- 首页优先显示照护待办、时限、人员、通知状态和处置记录；保留原先的绿色视觉系统。
- 单体后端 systemd 常驻运行配置、通知网关契约、备份和恢复指引。

## 无法仅靠代码/CI 证明的边界

- **未取得真实短信网关的生产密钥、运营商投递状态和现场设备**；因此不声称短信已在现实中送达。
- 未部署真实机构的 24 小时值守、应急联系人和运维监控。独立后台与一条值班升级短信不构成真正高可用。
- 未提供连锁多机构租户隔离、护理员岗位角色细分、原生 Android/手表端适配、网关高可用、生产数据库真实迁移回退演练。
- 没有独立完成整套隐私数据保留期限与合规性评估。代码中当前支持 ADMIN/FAMILY 两类账号，不应宣称已完成医疗机构级 RBAC。
- 2.0.4 的 ZIP 为源码包，不能直接安装运行；生产前需要安全评审、真实端到端验证和备份恢复演练。

## 正式生产验收

1. 真实设备触发 SOS：数据库事件/通知任务落库，弱网重发保持幂等，新事件可区分。
2. 通知网关真实发送：被拒绝、临时不可用、响应丢失、送达回执、回执签名过期和重复回执分别测试。
3. 值班操作：接单、处理、另一人复核、超时升级、后台退出或数据库重启恢复任务，保留完整审计。
4. 负载测试：事件积压、通知发送吞吐、超时任务积压和最长无人响应时间；不得只衡量“在线设备数”。
5. 运维验证： systemd 自动重启、DB/API/网关监控告警、备份恢复 RTO/RPO、联系人轮班和电话兜底渠道。
6. 组织权限与个人数据保护：岗位矩阵、敏感数据查看及导出留痕、数据最小化、保留期限政策。

**这六项属于生产交付必验门槛，不能以代码单元测试替代。**
