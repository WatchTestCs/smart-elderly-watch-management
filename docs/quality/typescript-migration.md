# 第一方 TypeScript 迁移

目标是全部第一方业务代码进入严格检查。当前 `tsconfig.json` 仍采用增量 include，
`checkJs` 尚未全局启用；一次绿色 `typecheck` 不能代表整个前端已经满足此目标。

首次全量审计在 `a52ebce` 上以 `strict: true`、`checkJs: true`，包含 `src/**/*.ts`、
`src/**/*.js`、`src/**/*.vue` 执行，报告 50 个文件共 819 条诊断。它们是迁移工作清单，
不意味着每条都是可见的运行时故障。临时审计配置和输出保存在隔离验收目录，没有替换
现有通过条件。现有会话代码另有独立 PR 修复，迁移时应先保留其行为和回归测试。

## 首批共享模块

| 模块 | 修改与边界 |
| --- | --- |
| `RecordCards.vue` | 使用泛型行和具名列描述；动态字段值在展示分支内缩窄，不将未知数据断言为业务 DTO；插槽保留行与索引；只对合法 VNode key 使用原值 |
| `recordActions.ts` | 使用真实 Element Plus 消息/确认签名、请求体 `unknown` 与响应 Envelope；保留删除二次确认、失败提示和刷新行为 |
| `useCollectionLayout.ts` | 使用原生 `MediaQueryListEvent`，保留监听注册和组件卸载清理 |
| `env.d.ts` | 声明实际注册的 `$message`、`$alert`、`$confirm` 类型，避免后续页面以隐式类型访问插件 |

记录卡片及其测试明确加入 typecheck；两个共享工具由既有 composables TS include 覆盖。
本批没有降低 `strict`、添加 `any`、忽略诊断或修改视觉基线。记录卡片测试覆盖空状态、
已处理与活跃告警、数值零、缺失值、展开字段和操作插槽。接入 API 客户端后本地 70 项前端测试、
typecheck 与生产构建通过。用隔离、无界面的 Edge 对生产包运行共享列表验收，124 项
检查全部通过，覆盖五类列表的加载/失败/重试、无效与空响应、窄屏和大字记录展开、
编辑行归属及操作保留。修正该脚本四处过时接口名并将其纳入每次 UI Quality，保留全部
原断言。API 流量全部模拟，不把结果当成真实后端或数据库验证；新提交的 CI 结果另查。

## 后续迁移顺序

1. 将动态分页 mixin 的请求、响应验证和取消逻辑整理成有类型的共享边界，再逐页接入。
2. 按业务模块迁移图表和设备管理，保持旧请求竞争、绑定隔离及写入语义。
3. 会话修复合入后迁移认证模块及入口，保留陈旧请求不得恢复旧身份的安全回归。
4. 补全各页请求/响应模型及输入校验，逐步纳入所有页面与第一方 JS；最后删除增量清单。

不能以声明文件把整页声明为 `any`，也不能通过缩减 include、关闭 checkJs 或批量断言
掩盖诊断。API 模型需要与实际响应及后端契约共同核对，不能仅凭前端使用方式猜字段。
