20 分钟实测的写入延迟 p95 / p99 为 **10.317 / 14.841 秒**；分析投影结束审计为 **2,763 已投影＋833 待处理＝3,596 新事件**，并未全部同步。MySQL 与 PG 查询均无错误，但查询形态不同，不能据此排名引擎性能。详细方法、数据规模、持久性与失败历史见 [API 修复报告](api-fix-report.md) 和 [压测汇总](stress20-summary.json)。

## 本次合入的行为

1. 保留远端最多一个连接的独立探测池，避免业务池耗尽误撤下 API；真实断库仍按故障处理。
2. 离线设备扫描每页最多 100 行，使用 `FOR UPDATE SKIP LOCKED`；规则历史基线采用来源索引及常见设备标识的覆盖查询，缩短设备行持锁时间。
3. 高频健康统计使用进程内 LRU 缓存：默认预算 **16 MiB**，最多 **2,048 项**、单项 **64 KiB**、入缓存后 **30 秒**过期。完整历史仍由 MySQL 磁盘持久化，PG 保存异步分析投影。
4. 命中仍先鉴权并核对已提交修订号；跨实例新增、更正和删除使旧结果不能命中。查询前后修订号变化则不入缓存，校验失败回查数据库。重启或淘汰后按持久化状态重建。

`HEALTH_HOT_CACHE_MIB=0` 并重启可禁用应用缓存。预算按结果 JSON 与估计元数据计费，不是进程 RSS 硬限制。持续上传或时间范围变化会降低命中率，未命中额外读取两次修订号；尚未测出持续写入场景下的缓存净收益。直接 SQL 维护必须遵守修订号协议；备份恢复或导入后应重启应用。
