# 多核缓存与健康批次内存布局（2026-10-23）

本轮基于 PR #30 的第一版 `8f530cc24452e0de2f92b4ad16f49ce4df7ac861`。此前第一版的真实 MySQL/PG 双库 CI 在 Go 1.23.2 与 1.27.2 均通过；本轮新增代码必须单独验证，不能沿用旧提交的绿灯。总架构分析见 [第一轮报告](../2026-10-23-hot-path/README.md)。

## 实现与硬件关系

### 1. SQL 模板缓存命中路径不再争用读锁

旧缓存每次 RLock/RUnlock 都会写同一读计数缓存行。现在采用 64 组、每组 8 路的固定数组快照：读者只取原子指针并读取不可变数组；每组仅在未命中时加锁、编译并复制发布下一快照。共最多 512 项已发布记录，退休快照由 GC 回收，因此该数字不是进程堆内存硬上限。

分组状态增加 128 字节间距，减少发布和驱逐时相邻组的伪共享；本机缓存行实际为 64 字节。短 SQL 使用随机种子的 maphash，长 SQL 只抽样固定 32 字节进行路由和候选过滤，再以**完整 SQL 字符串**验证命中。抽样碰撞只能降低命中率，不能返回其他 SQL 的计划。顺序绑定计划只保留参数数量，不再长期保存 `$1...$2800` 对应的 2800 个恒等索引。

这是不可变快照设计，命中路径没有共享计数写入；未命中路径仍有互斥锁，也会分配快照，不能将整个缓存描述为无锁或无分配。采用 Go 原子发布与 GC 生命周期，没有自定义 hazard pointer、unsafe、汇编或私有 runtime 接口。

### 2. 健康批次从复制结构改为字节索引

原 `final` 映射和 `events` 列表复制完整的 preparedSample，其中含多个字符串、时间、值指针和 metadata。超过 128 字节的 Go map 值还会产生间接分配。

现在每个归一化样本只保存一份，最终版本映射和事件列表保存 `uint8` 索引；读取时按索引访问原批次。200 条上限保证索引可表示，选择器再次拒绝超过 200 的输入，防止未来调用者静默截断。按输入顺序选择每个接受的中间版本，在保留 owner 时钟锁的情况下分配修订号；过期重复、相同版本内容冲突、规范化旧 JSON、删除标记及事务回滚规则不变。

### 3. 缓存完整 SQL，而不仅是 VALUES 片段

健康样本查询、批量 upsert 和 change INSERT 的完整语句按类型与 1..200 行缓存。每批不再拼接三个 SQL 字符串；同一形状共享不可变文本。缓存内没有健康值或请求参数。冷构建直接生成 VALUES，不在原片段缓存里额外保留同一份片段；缓存使用 3×201 固定槽，牺牲少量常驻文本以减少热路径临时分配。

## 本地对照

Go 1.23.12，Linux amd64，AMD EPYC 9V74；cgroup v2 CPU 配额 8 核、内存 8 GiB、缓存行 64 字节。缓存基准运行 GOMAXPROCS=1/4/8，每种 3 轮、每轮 400 ms；批次布局 5 轮、每轮 500 ms；完整语句 3 轮、每轮 400 ms。表中为中位数；同宿主、先后执行、无独占物理核保证。

`RunParallel` 的 ns/op 是总耗时除以总完成量，反映并发吞吐的摊销成本，**不是单个请求延迟**。缓存对照使用基线 worktree 和相同基准文件，计时轮次未启用 profiler。

| sharedSQL2800 | 8 | 33.83 | 5.482 |
| args14 | 1 | 16.04 | 23 |

`sharedSQL2800` 在各轮共用同一个不可变长 SQL，代表完整模板复用；`args2800` 每轮创建内容相同但存储不同的字符串，需要完整内容比较。`workingSet1024` 超出容量，各并发工作者循环相同的 1024 条 SQL；它不是随机独立到达模型。随机路由种子会影响碰撞分布。

**代价不能省略：单线程的短 SQL/共享模板缓存命中明显变慢；超容量场景部分并发档位也退化。** 该实现选择多核稳定工作集的吞吐，不能称为所有输入、所有 CPU 数都更快。若实际服务以单线程或大量临时 SQL 为主，应按原始表评估是否保留此改动。

批次布局只比较生产选择函数与从 8f530cc 保留的原算法 oracle，不包含 SQL、JSON 编码、磁盘或 HTTP：

## 维护约束

1. 不可原地修改已发布快照、参数位置向量或完整 SQL；修改必须构建新对象并原子发布。完整字符串校验不可省略。
2. 更改分组数时必须保持 2 的幂；提高批上限时，要同步检查 uint8 表示范围、选择器校验、SQL 槽数组、接口限制、数据库参数数及本轮边界测试。
3. 字节索引只能用于它所属的当前批次，不能跨请求保存、异步消费或归还复用池后继续引用。任何 arena/pool 改动必须重新证明生命周期。
4. 缓存失配增加时，退休快照与重复编译会增大 GC；64×8 仅是已发布项上限，分组 FIFO 不具备原全局 FIFO 的公平容量利用。
5. 本轮不改变业务连接池上限、GOGC、GOMEMLIMIT、goroutine 数、CPU affinity 或数据库可靠性设置。未测硬件 PMU/缓存未命中率，缓存局部性属于设计依据；性能结论限于已给出的对照。
