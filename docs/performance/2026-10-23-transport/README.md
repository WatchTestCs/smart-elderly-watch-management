# 参数传输与缓存回退修复（2026-10-23）

基于 `8a3da7c3795eff02e67beb0af0a87a95c3156704`，继续处理上一轮单线程缓存开销、工作集驱逐及真实 MySQL 没有吞吐收益的问题。本文件是当前实现说明；[上一轮数组快照报告](../2026-10-23-hardware/README.md)作为历史保留，不再代表当前缓存结构。

## 主要实现

1. MySQL 未显式配置参数模式时，使用 go-sql-driver/mysql 1.9.3 的插值协议，减少一次性 prepare/execute/close；不自行转义值。明确的 DSN `interpolateParams=false` 保持二进制协议。强制 utf8mb4、关闭多语句，重新校验驱动不允许插值的 collation。驱动对字面量问号或不适合插值的请求保守返回 prepare 路径。事务、隔离级别、行锁、提交与刷盘配置保持原样。
2. 健康样本、变更事件、规则、围栏和旧 PG 导入对 JSON 使用显式 `json.RawMessage`；二进制 BLOB 仍为 `[]byte`。这是参数类型的一部分，不应依据内容猜测普通字节是不是 JSON。
3. SQL 热缓存改为原生字符串 map 的不可变快照，返回不可变计划指针，消除自定义采样散列、8 路扫描以及计划结构的反复值复制。慢路径采用全局 FIFO，不再因分组碰撞提前驱逐。
4. 两张表分别最多 4096 项（热快照与可变 FIFO），允许额外常驻内存。32 次慢路径访问最多出现一个新形状时才发布快照；持续形状抖动时保留旧快照，避免每次未命中复制。编译在写锁之外，可能重复编译；命中不写共享统计计数。旧快照由 GC 回收，项数上限不是 RSS 硬上限。

## 参数模式与一致性验证

新增纯配置测试验证默认模式、显式开关、密码中的伪参数、Unix socket DSN、非法 bool 及不安全 collation。新增隔离 MySQL 传输测试分别使用二进制/插值模式、普通/NO_BACKSLASH_ESCAPES 会话：比较 Unicode、引号、反斜杠、问号、NUL、JSON、非 UTF-8 BLOB、微秒时间和 SQL NULL；通过会话 Com_stmt_prepare 计数验证插值路径不 prepare、字面量问号会安全回退。

缓存回归覆盖全键比较、并发编译、FIFO 容量、快照不可变、重复新形状最终提升及抖动不反复发布。原先的数组快照布局专属断言替换为新结构的同等行为测试；参数隔离、缺参和乱序测试继续运行。

本地完整短模式 race/build/vet/格式检查与真实双库 CI 分开报告；未配置数据库的本地用例是跳过。最终提交的 CI 和参数模式回归以 PR #30 对应 SHA 为准。

## 维护注意

- 程序新增 JSON 列写入必须明确参数类型；不把所有 []byte 自动改成文本。与旧字节参数依赖不兼容的部署可用明确 DSN false 回退。
- 热快照与计划指针不能原地修改；未命中统计仅在写锁下更新。不要为了命中率在每次读取增加共享原子计数。
- 4096 是两张表各自的项数限制，较原方案增加常驻内存；旧快照及字符串可能在 GC 前短暂留存。SQL 形状较多时必须监控内存和编译开销。
- 默认参数模式可以改变协议与 CPU/网络成本，不保证所有 SQL 更快；大 JSON 可能增加编码成本。所有业务持久性和错误处理必须保持。
