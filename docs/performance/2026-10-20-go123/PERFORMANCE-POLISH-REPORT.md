# Go 1.23 计算热点打磨报告（不包含数据库）

日期：2026-10-20。CPU：Intel Xeon Platinum 8573C；Linux amd64；Go 1.23.2。
所有下述吞吐数字均为 **CPU 内存运算或 JSON 编码**，并非 MySQL 写入、HTTP 接收、通知网关发送或送达速率。

## 核心变更

1. `internal/rules/compact.go`：将规则评估的结果转为定型的 `CompactCandidate`，避免每条结果创建大型 `map[string]any`；`EvaluateCompactInto` 接受调用方提供的容量为 7 的固定数组。输出是拷贝的值，不保留健康数据指针。
2. `internal/rules/engine.go`：生产规则引擎使用 `EvaluateCompactInto` 和新的证据编码逻辑；原有 `Evaluate` API 保留，证据字段与业务判断保持一致。
3. `internal/rules/evidence_fast.go`：对常用、无特殊转义的证据采用有界字节缓冲与定型 JSON 编码；非 ASCII、需要转义的输入及异常数值回退到 `encoding/json`。编码错误现在显式返回，不再隐式忽略。
4. `internal/health/identity.go` 和 `store.go`：对健康样本归属身份使用栈内 JSON 数组编码后做同样的 SHA-256；ASCII 快路径减少反射编码、接口装箱和中间内存分配。Unicode、控制字符、特殊转义及无效 UTF-8 走与旧代码一致的标准编码。**身份哈希值必须和旧版本完全相同。**
5. 加入规则旧实现对照、5,000 组随机业务条件、6,000 组证据 JSON 编码差异比较、5,000+ 组身份哈希等价测试以及固定运行脚本。没有引入第三方原生库、汇编、`unsafe` 或改变通知可靠性机制。

## 最终独立基准（单核运行，`GOMAXPROCS=1`）

| 场景 | 原实现 | 新实现 | 说明 |
|---|---:|---:|---|
| 规则评估、7 类候选中的最多 7 条 | 3.9–4.2 µs/次；54 次分配、3,986 B | `EvaluateCompactInto` 0.48–0.60 µs/次；3 次分配、80 B | 纯规则运算约 167–210 万次/秒，不含证据序列化 |
| 规则评估 + 当前固定测试数据的全部证据 JSON | 约 45–56 µs/次；244 次分配、约 15.9 KB | **约 4.4–5.9 µs/次**；10 次分配、2,768 B | **约 17–23 万次/秒**，部分测次达到 20 万；持续稳定超过 20 万尚未证明 |
| SHA-256 健康样本身份哈希 | 1,108–1,129 ns/次；10 次分配、400 B | 335 ns/次；2 次分配、128 B | 哈希值和旧代码完全一致 |
| 健康样本 Normalize + 标准 JSON + 身份哈希 | 2,828–2,916 ns/次；15 次分配、968 B | 2,043–2,257 ns/次；7 次分配、696 B | **约 44–49 万条/秒的纯计算路径**，非写入 |

不同运行会受到 CPU 频率、垃圾回收、测试持续时间和系统负载影响；表中为实际多次测量区间，不能作为 SLA 或容量保证。重复运行脚本测到一轮 5.916 µs，不隐去较慢测次。

## 验证边界

- 已通过：独立 Go 1.23.2 规则/健康模块测试；`go test -race`；`go vet`；5,000 组旧规则与新规则比较；6,000 组证据 JSON 语义比较；健康身份哈希含中文、转义、非法 UTF-8 的 5,000+ 组一致性检查；Go 源码格式检查（一个历史文件此前已未格式化）。
- 尚未验证：完整后端 `go test ./...`；本环境没有缓存完整 `github.com/jackc/pgx/v5`、MySQL 驱动等第三方模块且无法下载；生产 `engine.go` 的数据库集成编译及运行未覆盖。真实通知、网络、持久化、弱网恢复与完整多实例集群压测均未开展。
- 数据兼容：原 `Evaluate` 返回独立 map 的旧接口保留；新证据 JSON **字段/值等价，但字段排列顺序可能不同**。SHA-256 身份哈希字节级相同。
- 注意：本次规则 JSON 快路径遇到异常数字将把编码错误显式返回；旧实现忽略错误可能悄然写入空证据。这属于安全性收紧，异常数据应由上游阈值校验拒绝。
- 汇编没有成为瓶颈解决方案：旧代码主要耗时于动态 map、反射和分配，Go 定型结构与缓存更快、更易维护且同时可在 amd64/arm64 使用。

## 可复现方式

解压本源码 ZIP，在项目根目录执行（Go 1.23.x）:

```bash
python3 scripts/go123-perf-polish.py
```

该脚本将原封不动复制 `internal/rules` 和 `internal/health` 中的纯计算生产文件到临时小模块，分别运行竞态测试、`go vet` 和实测基准，不需要 MySQL，不会修改源码。健康模块使用临时隔离测试夹具声明 `Owner` / `Digest`，该定义与生产源码一致；这不是完整后端测试。

## 后续推荐顺序

1. 在依赖齐全的 Go 1.23.2 构建机上完整编译、运行回归；先验证 `engine.go` 集成与证据 schema 不变。
2. 对常见非 ASCII 设备名称构建真实流量分布基准，决定是否要优化当前的回退路径。
3. 压测规则引擎并发吞吐与 GC，保留 p50/p95/p99 延迟及错误率，不能仅凭最佳值宣布稳定 20 万。
4. 在端到端数据链路上独立评估网络、数据库和通知 Outbox，不以这些计算基准替代。
