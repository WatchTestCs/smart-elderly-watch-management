# 算法与架构迭代记录 · 2026-10-26

基线：`preview@8c22299dafe2760c878f74806b0848b29257cc43`。本轮检查启动、采集、统计、规则、围栏、通知、分析、数据库缓存、会话及前端读取/渲染的主要实现，完成三轮修改与复核。交付的是下述有证据的改进，不代表每个函数、每种输入或整个系统已经达到最优。

## 保留的修改

| 模块 | 原有成本或缺陷 | 最终实现与边界 |
| --- | --- | --- |
| 普通数值统计 | 保存所有有效样本指针，再遍历求和，临时存储 O(n) | 按原输入顺序直接累计，临时状态 O(1)；保留混合身份、未知时区的拒绝及原浮点运算顺序 |
| 日累计统计 | 每条观察保存指针后再只选每天最新值 | 仅保留每天最新样本，临时存储 O(d)，d 为报告天数；原有同一观察时刻冲突检查仍保留 |
| 睡眠冲突区间 | 已排序的两组区间又复制两次、合并排序 | 线性归并两组已排序区间；最终冲突计算从 O(n log n) 降为 O(n)，这一阶段无合并副本；各睡眠阶段仍需排序，整体仍为 O(n log n) |
| 限流 | 所有 IP 共用一把锁；每次遍历窗口时间戳；每次分配组合字符串 | 32 个分片、IP/路径结构键、精确环形 FIFO；每个时间戳最多过期移除一次，窗口检查摊销 O(1)，已满窗口拒绝 O(1)；新 IP 从 1 个槽位起按需扩容，最多达到配额 |
| 限流生命周期 | 清理 goroutine 没有退出入口 | 增加幂等 Close，由服务及测量夹具关闭；清理逐分片只检查最新命中的时间戳 |
| 设备协议命令 | 每次拆分并线性查找固定型号字符串，产生 480–720 B 临时分配 | 初始化一次静态查找表；S6T 保留直接分支，未知型号与不支持的操作仍拒绝 |
| 监护人与照护任务列表 | 加载时丢弃后来的查询；旧响应可能覆盖当前页；确认保存后的刷新可能被丢弃 | 共用读取调度器：一个在途读取、一个可覆盖的最新待执行读取；过期成功/失败不更新界面，等待者等到队列排空；卸载后不启动后续读取、不提交迟到结果 |

读取调度器只用于两个查询端点。保存、删除、照护状态转换仍只执行用户发起的那一次操作；成功后显式排队读取确认后的视图。它没有取消已经在网络中的读取，因此在途操作仍可能消耗服务端资源和请求超时；它限制的是后续请求数量与界面提交顺序。

## 迭代中修正的取舍

1. 第一版统计快速分流可能重复扫描全部删除/无值的输入。最终找到首个有效样本后裁掉无效前缀；没有有效值时直接返回空结果，并补入全删除的大规模基准。
2. 第一版环形窗口一次性分配完整配额。复核发现这会放大只访问一次的 IP 的时间戳存储，改为 1、2、4……直至配额的按需增长；单次、环绕后扩容、满配额及精确过期边界均有回归。单键有界不等于进程总内存有硬上限：活跃 IP 数仍未设全局硬配额。
3. 日累计进一步从保存全部样本降到仅保存每日样本。S6T 保留原直接判断，避免强制经过哈希表。没有放宽统计冲突、身份或时间语义来获得数字。

## 最终局部基准

Linux amd64，Go 1.23.2，AMD EPYC 9V74 80-Core Processor；cgroup CPU 配额 `800000 100000`，共享环境，未绑核。分别使用 GOMAXPROCS=1/4/8。每项数字是两次运行的算术平均；下表大规模统计换算为 ms/op，其余为 ns/op。仅两次运行，不能据此宣称统计显著性或生产 SLA。

健康统计与命令解析按 A3 → B3 → B4 → A4 交替，各项 200ms；限流按需扩容修正后最终按 A7 → B7 → B8 → A8 交替，各项 300ms。两版本运行相同夹具。生产源码和夹具 SHA-256、每轮命令见 [environment.json](evidence/environment.json)。

**保留全部方向的数据。** 1,000 条步数区间控制场景单 P 约 +0.6%，S6T 在 GOMAXPROCS=4 下为 5.605 → 6.152 ns（+9.8%）；不能说所有路径都更快。初始 A1/B1/B2/A2 中还观察到小规模区间场景约 +6%，没有删除。A1 开头与前端验证短暂并行，仅作探索记录；最终对照在验证结束后执行。A5 返回退出码 0，但保存的日志缺少最后两行基准和 PASS，按不完整输出排除，完整重做 A7/B7/B8/A8。详见 [全部汇总](evidence/summary.json) 与原始日志。本轮没有重测真实数据库 HTTP p50/p95/p99，不能把上述数字当作整站提速。

## 正确性与验证

- `go test -race -short -json ./... -count=1 -timeout 180s`：最终生产实现 **890 项测试/子测试通过，125 项跳过，0 失败**。跳过原因逐项保留在 [backend-race.txt](evidence/backend-race.txt)。未配置独立 MySQL/PG 测试连接；数据库集成及 opt-in 测试不算已验证。
- 统计以固定基线函数作独立 oracle，3,000 组随机输入对照结果、错误与浮点位；覆盖普通数值、日累计、步数区间、睡眠、删除/无值、混合来源及未知时区。原有大整数步数分摊、跨日守恒、日历/DST 与调用者所有权测试继续执行。日累计沿用 map 的遍历顺序，原有非整数跨日求和的浮点次序不确定性没有建立新契约。
- 环形窗口与旧扫描算法进行 80,000 次确定性事件对照；并发同 IP 只接受配额次数，清理并发、IP/路径隔离、IPv6、伪造转发头、环绕扩容、边界及关闭均回归。
- 前端 **19 项测试通过**，含 1,000 次读取突发只执行在途与最新后继、过期失败、重入页码修正、卸载清理、保存确认后刷新。三个缺陷测试在基线均按预期失败，见 [baseline-ui-regressions.txt](evidence/baseline-ui-regressions.txt)，在最终代码通过。Vue 组件检查使用 happy-dom 与替身 API，不是实机或真实浏览器验收。
- `go build ./...`、`go vet ./...`、`go mod verify`、OpenAPI 生成契约、`npm run typecheck`、`npm run build` 通过。Vite 仍报告现有大于 500 kB 的 chunk，未将其描述为性能改进。Go 1.27、远端 CI、真实数据库、真实设备、Windows 原生壳和长期负载以相应实际检查为准。

## 检查后保留的架构

| 范围 | 本轮判断 |
| --- | --- |
| 采集与版本选择 | 保留 200 条有界批次、批内 uint8 索引、设备/owner 锁顺序和 MySQL 提交确认；没有使用异步“先成功后落库” |
| 步数与围栏 | 保留 128 位乘除的整数步数分摊、重叠拒绝、局部 WGS84 合同与去抖；围栏配置自交检查 O(v²)，定位包含检查 O(v)，顶点有界；没有引入近似距离或降低精度 |
| 规则计算 | 保留 keyset 扫描、每设备事务、最多 8 个工作协程、紧凑证据和覆盖索引；满页立即继续扫描的逻辑已有，无需重复“优化” |
| 通知与照护 | 保留持久 outbox、有界认领、租约条件更新、通知与人工接单/复核状态区分；不改现有回执、岗位与隐私 PR 的实现 |
| 分析投影 | 保留 MySQL 为主、PG 可重建投影；先 PG 提交再确认 MySQL，按事件版本幂等；保留事务内触发器，避免丢失入队 |
| 数据库缓存与会话 | 保留 4,096 项 SQL 计划缓存、连接内有界语句缓存和请求内会话复用；没有增加跨请求权限缓存或修改数据库持久性 |
| 前端与桌面 | 保留路由懒加载、图表实例不进入响应图、按需地图与 Tauri 生命周期；本轮仅调整两个列表的读取调度 |
| 部署与尚未合并工作 | 检查时 #27、#29、#32、#33 开放，未合并它们。#32 会扩展限流路径，后续应基于本轮 preview 核对限额与回归；本轮不替代这些 PR 的独立部署/安全验收 |
