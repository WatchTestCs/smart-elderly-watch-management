## 新增检查实际覆盖的行为

- 真实传值 K1/C16 的定位映射、S6T `resetq`、未知类型和不支持动作拒绝；不把枚举标识符作为接口传值。
- 指令入队幂等、不同动作冲突、设备认证、两个并发领取请求只有一个领到同一任务、普通采样不确认指令、伪造/旧投递令牌拒绝、相同最终回执可重放、冲突结果拒绝。
- 非安全动作超时后不重发；安全动作重投保留指令 ID、更换令牌；新 Handler 能读取既有持久化任务；旧绑定回执拒绝及旧队列取消。
- 日结果 pending/ready、来源精确隔离（包括 source 列采用不区分大小写排序规则时的 watch/WATCH）、修订跨日后旧日清空、新日重算、删除后重建及家属越权拒绝。
- 多边形边界与自交校验、坐标维数校验、跨午夜时段、连续点和持续时间、首点不伪造进入、乱序/重复点不生成事件。
- 围栏离开事件关联现有照护任务、旧 revision 编辑拒绝、停用后不再判断、未知坐标系拒绝；通知网关模拟接收的类型为 `care.fence_exit`，只记 sent，不冒充 delivered。
- SOS 的独立复核写入 false_alarm 结论；心率具体记录的并发版本冲突拒绝、后续更正保留之前的复核历史；家属不能调用主管接口。
- 新增敏感读取有审计；审计存储不可用时阻止披露。
- 在默认 latin1 的空数据库应用新增迁移，指令表仍为 utf8mb4_bin；执行回滚、再次正向迁移和重复迁移；修订时钟保持 42，已生成照护履历仍存在。

## 修正过的问题及复验边界

首轮日结果注册因通用 SQL 适配器把冲突忽略转换为 `id=id` 而返回 500，已改为明确操作 `cache_key` 的 MySQL 语句。硬件权限测试原先向三个不同接口发送同一混合请求体，被严格字段校验先拒绝，已按每个接口的请求形态修正。源文件格式检查发现并规范了本次新增文件的格式与换行；迁移脚本最终字节保存后另行复核了回滚/重建。

这些结果是本机源码与隔离数据库检查，不等于远端 CI、真实设备、网关或生产验收。

1. 未验收真实手表。启用 commandProfile 前，固件必须实现岁宁拉取、commandId 去重与执行回执；本次不是既有商业设备的即插即用通信驱动。
2. 围栏要求明确 WGS84、精度与事件时间；未把无坐标系的旧轨迹自动用于围栏，也未将配置同步到设备侧。
3. 未运行实际通知供应商。模拟 HTTP 网关仅验证事件类型与渠道接收状态；送达仍需现有签名回执。
4. 未新增 UI 页面或安装程序，误报选择等客户端接入需使用文档中的后端接口；未发布 Release，也未修改版本号或 main。
5. 未执行生产迁移/回滚、长时负载、空间算法全球精度或大规模队列验收。日结果采用保守失效与时钟锁，需按真实负载评估吞吐。
6. 未为未知异常事件编造 duration、confidence 或商业类型值域；新复核结论和既有解除状态相互独立。
