# 当前本地源码：MySQL 主库 + PostgreSQL 分析库

本轮源码使用双库，配置与迁移步骤见 [DUAL_DATABASES](DUAL_DATABASES.md)。历史公开安装包不支持此配置。本地曾构建 2.0.6，但未包含后续健康采样整合；本次推送的整合源码需重新构建，详见 [整合记录](INTEGRATION_2.0.6.md)。

1. 准备专用空 MySQL 业务库，以及独立 PG 分析库。数据库由部署方管理。
2. Go 使用 `MYSQL_DSN`、`PG_ANALYTICS_URL`；桌面使用 `SUINING_MYSQL_DSN`、`SUINING_PG_ANALYTICS_URL`。修改后重启，凭据只保存在部署环境。
3. MySQL 完成迁移后开放业务，首次空库创建管理员，无默认通用账号。PG 同步独立重试，断线时核心业务仍走 MySQL。
4. 先建老人档案，再到设备管理登记、绑定；档案编辑不修改归属。主设备移除后保留剩余设备中的最小编号。
5. SOS 支持接单、处置、另一名主管独立复核；关闭对应告警并刷新统计，记录可查。护理员/审计员岗位仍只约束照护功能。
6. 主管在值守诊断查看 PG 状态、积压量和最近同步时间。通知网关与回执配置仍按 [照护部署](CARE_SERVICE_DEPLOYMENT.md) 执行。

MySQL 断线时保留界面和退出登录，业务提示暂不可用，恢复后重连。失败业务写入不自动重放；分析队列只重试已提交成功的事件。

旧 PG 数据通过 `go run ./cmd/transfer-postgres` 预检查，停止两端应用写入后用 `--apply` 导入空 MySQL；源库只读，目标非空时拒绝导入。图片另行备份及复制。旧 H2 不会自动转换。

本地 `%APPDATA%\岁宁` 保存图片、日志与运行发现文件。MySQL 是业务备份与恢复依据，PG 投影可重建。测试库不与生产数据混用。
