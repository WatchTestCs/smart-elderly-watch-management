# v2.1.0 综合优化包评审与采纳记录

来源：上传的 `suining-v2.1.0-comprehensive-optimization.zip`。评审基线为 GitHub `preview` 分支 `4aefaa46508afe70f1f8b1864f7cd23afa229b76`。

该 ZIP 包含 42 个源码/测试文件及一份说明，其中大部分继承了上一份 GA readiness 补丁，已在独立的 PR #205 中处理。本 PR **不重复导入 PR #205 或直接覆盖 `preview`**，仅摘取对当前代码有实益的剩余改动，并修复包内未覆盖的边界问题。

## 采纳（经适配）

| 范围 | 调整 | 验证重点 |
| --- | --- | --- |
| MySQL 主池与探活池 | 空闲连接最长保留 2 分钟，保持原有 5 分钟连接生命周期 | 原连接池、MySQL 读写及探针回归 |
| 登录会话 | 用户初始化判定从 `COUNT(*)` 改为 `EXISTS`，响应结构保持不变 | 匿名、管理员及家属会话契约 |
| 设备验签防重放 | 过期 nonce 每轮最多 4 批，每批 `DELETE ... LIMIT 5000`，固定本轮截止时间 | SQL 与批次数量的纯单元测试；真实 MySQL 回归 |
| 照护通知网关 | 不配置自定义 CA 时仍明确最低 TLS 1.2、资源限制和超时 | 不使用外部网络的客户端配置测试 |
| 照护回执、网关、普通/批量通知 | 秘钥与 provider App ID 使用已有 `config.Secret()`，支持 `*_FILE`；对小响应有界排空，连接按条件复用 | 文件密钥、真实回执验签、通知契约 |
| 腾讯短信 | 预编译校验正则、最多 64 KiB 的响应体、完整 JSON 校验，**必须显式返回 `result: 0` 才接受** | 200 + `{}`、错误码、超大体、尾随 JSON、正常确认 |

**注意：**有界排空 4 KiB 并不保证任意大小响应都可以复用 Keep-Alive 连接；较大响应被关闭是预期的安全边界。`SetConnMaxIdleTime` 也是降低闲置陈旧连接风险，不能替代网络/数据库探活。

## 拒绝/延后

- **统计缓存 Singleflight 及放开事务**：上传实现会在完成授权读事务后，才重新读取统计样本。岗位/授权和数据可能在两步间改变，需要重新设计同一权限快照的校验、并发取消和多实例一致性，再谈缓存防击穿。
- **HTTP 指标中间件统一 `recover()`**：若 handler 已发出 2xx 响应再 panic，无法把真实响应改成 500，上传版本却给监控记录 500；恢复策略应和最外层错误处理、流式响应及隐私日志一起评估。
- **`response` 的 `sync.Pool` 重写、手写 HMAC 微优化、腾讯通知全量 `goccy/go-json` 改写**：无相同负载条件下的分配/吞吐基准，额外路径增加了生命周期与可维护性复杂度；此次保留现有正确实现。
- **整包剩余的 GA readiness 配置/CLI/CSRF/前端轮询/Rust 测试**：属于未合并的 PR #205，不再复制，避免冲突和重复回归。
- **“100% 兼容”“全部高收益、低风险”“最终 GA 就绪”** 等声明：没有真实生产数据、设备、性能基线和发布验收支撑，不能认定成立。

## 运行和验收

代码不修改 `/api/v1/*` 路由、数据库迁移或依赖清单。每次 PR 应通过对应的 Go 静态检查、MySQL/race 回归、告警/回执集成、安全扫描。正式 GA 另需真机、升级回滚、通知网关真实连通及发布构建验收，不能以本 PR 合并替代。
