# 数据库独立部署与非阻断连接（历史验收）

> **历史记录（2.0.2 时代的 PostgreSQL 业务主库／内存会话）**：本文保留当时的实现与验收结论，并非当前 `preview` 默认 MySQL 业务主库和数据库会话的配置指南。参见 [现行架构](ARCHITECTURE.md)、[平台升级说明](PLATFORM_UPGRADE_2.0.6.md)。当前默认数据库会话的登出需要 MySQL 完成服务端撤销，断库时可能返回 503；旧版“离线登出成功”不是新版保证。旧环境变量 `DATABASE_URL` / `SUINING_DATABASE_URL` 不再是当前 MySQL 主库的配置入口。

数据库与软件分离是产品策略，安装包不托管 PostgreSQL。软件能独立打开，不应让数据库连接状态替代整个界面。

## 当前行为

- 无数据库启动：直接显示登录界面，字号、密码显隐和窗口操作可用；登录等数据库操作就地提示不可用。
- 已登录后断线：保留当前工作区、路由与本地输入；相关查询或写入提示连接不可用，不伪造业务数据。
- 自动恢复：Go 在后台重试数据库连接；前端跨页面探测状态并监听联网事件。恢复后重新检查会话，已失效会话仍需登录，不绕过角色权限。
- 退出登录：独立本地会话端点，不依赖 PostgreSQL，仍需有效会话与 CSRF，退出后销毁服务端会话。
- 失败操作不自动重放；未保存的输入保留，由用户恢复后确认并提交。

自动连接的目标必须由部署方事先配置 `SUINING_DATABASE_URL`（直接 Go 启动使用 `DATABASE_URL`）。软件不能仅凭联网自动推断数据库主机、账号和密码；网络在线也不代表数据库可用。配置变更后需重启软件以读取新配置。没有默认通用账号。

## 验收

新增浏览器回归先复现了旧版的全屏连接页问题，再验证非阻断登录、离线本地控制、未认证拦截、联网恢复、已登录导航、输入保留及无写入重放。数据库无关退出测试也先复现旧版 503，再验证无数据库仍可销毁会话且缺少 CSRF 被拒绝。

实际验收：Windows 前端生产构建、Go 真实 PostgreSQL 回归、静态检查和 Tauri/NSIS 构建通过；WSL/Linux 配合真实 PostgreSQL 的 Go 竞争检测通过；9 组浏览器回归共 1232 项通过，其中新增数据库可用性 13 项。真实 Tauri / PostgreSQL 13 项断开恢复检查全部通过，包括原生初始化表单保留、工作区导航与草稿保留、离线退出登录及防重放。最终轻量 Setup 已实际安装、启动和卸载，用户数据保留。强制断库时观察到预期的 503 及少量进行中 SQL 请求的 500，页面未出现未捕获异常；不宣称断库期间所有接口仍成功。本次按用户要求替换现有 2.0.2 Release，版本号保留。

## 2026-10-22：当前 MySQL 高负载下的探测与维护

以下为当前 MySQL 主库实现，独立于上面的 2.0.2 历史验收。修复、双库复测及缓存证据见 [2026-10-22 后端报告](performance/2026-10-22-backend-hybrid/README.md)。

健康统计的热结果可保存在有界进程内缓存中，`HEALTH_HOT_CACHE_MIB` 默认 16、0 禁用；每次仍执行鉴权及数据库修订号核验。数据库不可用时不会依靠旧缓存伪造成功，全部采样与修订事件继续事务持久化。此缓存不改变登录、登出或故障恢复的保证。

业务连接池上限为 20，连接繁忙不等于主库断开。后台就绪检查使用独立、最多一个连接的探测池，仍执行真实 MySQL Ping，连接失败时继续撤下业务 API 并返回 503。部署时需为该探测连接保留数据库连接额度。

离线设备扫描按每批最多 100 行领取，跳过其他事务正在锁定的设备，在下一轮重新检查。规则基线迁移 `0008_rule_baseline_source.sql` 添加来源前缀索引，查询继续核对完整二进制来源，避免合并大小写或前缀相似的数据。索引需要构建时间及磁盘空间，请在维护窗口完成升级，失败写入仍不自动重放。

`0009_rule_baseline_cover.sql` 为长度不超过 64 字节的来源设备标识提供基线覆盖查询，聚合直接读取索引中的数值与时间标记，不逐条回表读取 JSON。数值和标记由原始 payload 自动生成，不维护第二套业务数据；完整二进制来源比较及时间窗口保持不变。更长的标识保留原查询路径。升级也需要为索引构建预留空间与时间。
