# ADR-0005：preview 预发布与交付模型

- Status: Accepted
- Date: 2026-10-16

## Context

项目需要在不影响 `main` 的情况下进行桌面预发布、验收与交接。历史上已有较完整的一次性打包/签名/安装验收，但缺少持续可重放的流水线。

## Decision

当前工程化工作以 `preview` 为唯一目标分支。预发布资产必须能追溯到唯一 commit SHA，并经过分层门禁：

1. 前端构建与依赖检查；
2. 后端测试；
3. UI/a11y/视觉检查；
4. Windows 桌面 smoke；
5. 安装、覆盖升级和卸载边界；
6. 签名、摘要、SBOM/来源证明。

普通 PR/CI 不读取发布私钥。签名与发布只在明确的 release 流程中发生。

## Consequences

- `main` 不作为当前预发布自动化的隐式目标；
- “本机测试过”不能替代仓库可重复命令；
- 发布文档必须区分自动证据与人工验收；
- 发布失败不得通过跳过祖先门禁或直接替换资产来掩盖。
