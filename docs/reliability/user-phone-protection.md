# 管理员手机号保护与受控回退

这一批仅覆盖 MySQL `users.user_phone`。家属、长者、客户、社交内容、姓名/地址及健康字段仍在后续迁移范围；不能据此关闭 P0-06。PG 旧主库 schema 同步扩列用于兼容性回归，不改变应用主库选择，也不增加 PG 故障切主。

## 存储与查询约定

`mysql/0021_user_phone_protection.sql` 是扩列迁移：新增随机 AEAD 的 `user_phone_cipher`、独立 HMAC 查询列 `user_phone_lookup` 和明确的 `user_phone_protected` 标志。历史 SQL 不改动。`user_phone` 的 NULL/唯一约束保留，新的 HMAC 列也具有唯一约束，存储标志索引支持缺 key 检查。CHECK 约束阻止受保护行同时保存旧明文，或只写入密文/索引其中一项。HMAC 使用 `account-phone` 域；keyring 模式沿用独立 lookupKey，旧单 key 配置沿用其既有 HMAC key，不在这一批擅自切换 C，不能以裸 SHA 替代。

选择扩列而非把密文塞进旧 varchar 查询列，是为了保留历史读取与受控回退；随机 AEAD 避免确定性密文的相等性暴露，精确查询单独使用有域的 HMAC。没有把可枚举手机号的裸哈希作为保护，也不在此阶段增加模糊搜索。新表只存固定 HMAC 校验值，读取实际密钥仍依赖外部受控配置。

密文 AAD 绑定管理员角色和稳定 `user_id`：`account-phone:admin:<id>`，防止跨账号、跨角色复制。读取同时认证 AEAD 和 HMAC；错误/缺失 key、损坏密文、错误摘要不回退旧明文。尚未迁移的行保留旧读取行为。NULL 手机号保持 NULL，不变为空串。迁移只接受原样有效的 11 位手机号；异常历史值需要单独纠正，不自动 trim、重写或丢弃。

`account_phone_key_state` 仅保存独立 HMAC 的固定版本校验值，首次受保护写入前注册，后续写入不能覆盖它。查询核对该绑定，防止配置了错误 lookupKey 后把所有受保护管理员误判为不存在并遗漏跨角色查重。校验值不含密钥，不能作为查询索引替代；缺失或不匹配时失败。回退保留该绑定，再升级沿用同一 lookupKey。PG→MySQL 离线导入在源表存在时一并迁移绑定，旧源没有该表时保持旧行为。

新 setup 在原有初始化事务和 `app_metadata` 行锁内取得 ID，再密封并写索引；事务中不插入明文手机号，缺 key 时整笔回滚。登录和管理员精确查询兼容旧/新行，HTTP DTO、session 中的授权手机号及管理员优先的历史跨角色登录顺序保持原样。家属创建、更新及两种邀请码注册分支的查重同时检查受保护管理员。没有 key 且存在受保护行时查询失败，不把这些账号当作不存在；仅有旧行的开发回归库仍可读。

## 扫描、回填与轮换

使用经过本批验证的程序，先让启动迁移完成，再单独执行 `cmd/protect-user-phones`。连接和 key 仅通过受限的 `MYSQL_DSN_FILE`、`DATA_ENCRYPTION_KEY_FILE` 或既有 secret 机制配置；命令不接受连接串或 key 作为 CLI 参数。不在命令行、日志、工单或证据中粘贴 secret。

```powershell
# 已注入仅指向目标实例的私有配置；默认只输出聚合扫描报告。
go run ./cmd/protect-user-phones
# 已停用全部写实例并确认恢复用备份后，预检、回填、再扫描。
go run ./cmd/protect-user-phones --apply --batch-size 100 --max-rows 1000000 --pause 20ms --timeout 15m
```

首次写入前遍历并认证完整选定范围。按 ID 高水位分页，页最多 1000 行；单密文字段超过 4096 字节不读入正文而标为异常。行数、暂停和整体超时均有界。SQL 固定，更新以 ID、旧存储标志及旧明文/密文/索引的二进制 NULL 安全比较做 CAS，避免 MySQL 比较规则吞掉大小写或尾空格差异。每行独立提交，冲突、约束失败、异常、取消、预算耗尽和前后行数变化均非成功；修复原因后从扫描恢复。预检不能消除随后发生的并发修改，也不把分批迁移宣称为全库原子事务。

停止全部写实例是这一阶段的运维前置条件，命令不会验证或伪造跨实例写版本屏障。仍需另行落实该屏障和部署自动化。扫描不改变行；保护模式在认证后跳过已使用当前 key 的密文，重复运行不重新随机化它。若切换 AEAD active key，保留旧 readers 和相同 lookupKey 再执行同一命令，可重封装本字段。lookupKey 改变导致认证失败，不能借这个命令重建查询索引。`rekey-data` 的固定 19 字段和事件载荷范围不自动扩展到本字段，由本命令单独处理。

报告只含范围、阶段、数量、重写和冲突数，不包含行 ID、手机号、密文、索引或 SQL driver 详细错误。`selected_scope_clean` 仅针对当前 `users` 扫描的指定形态；`retirement_authorized` 始终 false。binlog、WAL、复制、对象、历史 SQL dump 和旧备份可能保留明文或依赖旧 key，不能据实时扫描删除 reader。

## 回退与再升级

代码回退前停掉全部写实例，保留新旧程序、原配置及经过隔离恢复验证的备份。在同一私有配置下先扫描；确认能认证全部密文后运行：

```powershell
go run ./cmd/protect-user-phones --apply --rollback --timeout 15m
```

回退以相同 CAS 还原原手机号，清空新密文/索引，恢复旧存储标志；NULL 保持 NULL。只有成功、残留 protected 为 0、行数一致后才可启动相容旧程序。错误 key、残留、冲突或失败时保留新程序和全部所需 readers，不启动缺乏新字段读取能力的旧程序。失败可能已完成部分行的回退，必须排查后扫描恢复，不删除数据制造成功。

新增列、约束和迁移账本可保留，旧程序忽略其不认识的扩列。`rollback/mysql_0021_user_phone_protection.sql` 按既有回滚套件约定仅撤销这条迁移登记，保留所有列和值；它不会解密数据，也不能替代上述回退命令。重新运行当前 MySQL 迁移能恢复登记，随后保护命令可再回填。本批验证包括真实 SQL 存储回退/再应用和当前 HTTP 读取；任意历史可执行文件的安装降级及协调备份恢复仍需另外实测，不将 SQL 回退等同全部恢复验收。

MySQL 在重放多动作 ALTER 时可能先报重复 CHECK 名称，而非重复列。这里不全局忽略 3822：对 0021 的扩列步骤逐一核对列类型、NULL/default/collation/非生成属性、完整可见索引及唯一性、CHECK 真实表达式与强制启用状态，只有完整相同才跳过。比较保留括号、操作符和引用字节；不认识的服务端表达式格式也会失败，需单独审查。初次扩列后、后续建绑定表前中断可以重启；半套 schema、弱化/禁用 CHECK、截断索引、错误默认值/排序规则均拒绝自动跳过或“修复”。历史 SQL 字节和已登记摘要不为此改写。
