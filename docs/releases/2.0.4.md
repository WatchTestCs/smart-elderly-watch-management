# 岁宁 2.0.4 · 求助照护闭环（源码预览版）

本次版本面向“求助有人接、处置有记录、后端能独立运行”三个优先目标。相较 2.0.3 的代码结构维护，此版本新增了照护事件工作流的实际实现。

## 功能和可靠性变化

- **SOS 事件与通知状态分离**：设备求助写入独立事件、审计履历，消息明确告知只是“已接收”，不再提前声称家属已获通知。
- **弱网重试去重**：设备以 `requestId` 标识同一次 SOS；重复请求复用原事件，避免无谓生成重复告警。旧设备未提供 requestId 时，不能保证重试去重。
- **可靠通知基础链路**：关联家属通知任务与 SOS 原子落库；持久化任务轮询、重试、重启恢复；经配置的 HTTPS 网关接受才记 `sent`，带签名的真实送达回执才记 `delivered`。
- **人工接单和责任链**：管理员查看待办、接单、开始处置、填写处理说明、独立第二人复核关闭、审计履历，超时自动标记升级并可创建值班通知任务。
- **任务优先的首页**：照护待办展示在既有统计与公告之前，包括长者、等待时限、责任人、通知状态及处理历史；保持原绿色视觉风格。
- **独立运行方案**：新增 systemd 常驻服务配置、通知网关契约与恢复诊断文档；桌面退出不再是机构运行模式下必须停止独立 Go 服务的理由。
- **测试**：新增 PostgreSQL 集成测试，覆盖事件落库、通知待发、管理权限、审计、二人复核、签名回执、弱网去重、发送状态区分和超时升级。

## 关键警告

**本 Release 是源码预览版，不是经过真实设备、短信运营商和机构值守验收的生命安全保障系统。** 未配置 `CARE_NOTIFY_WEBHOOK_URL`、`CARE_NOTIFY_WEBHOOK_TOKEN` 等网关变量时，通知只会保持待发而不会自动送达。不能将软件“收到求助”、网关“已接受”、家属“已收到”、人员“已接单”混作一件事。

详细部署及网关对接：`docs/CARE_SERVICE_DEPLOYMENT.md`。真实交付门槛：`docs/CARE_2.0.4_GATES.md`。

**仅发布源码 ZIP，不包含 Windows 安装版、Linux 安装程序、真实短信网关或生产数据库。**
