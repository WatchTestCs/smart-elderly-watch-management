# 岁宁 2.0.6 改进说明

日期：2026-10-19。基于 2.0.5-optimized.1 及本轮 UI、照护闭环和双库补丁整理的本地交付。现有后台权限范围保持不变。

## 一、界面更完整

- 统一侧边栏、页面标题和功能术语；导航只展开当前路由所在组，避免菜单默认全开溢出。
- 老人档案在窄屏使用完整资料卡片，保留编辑、删除入口；宽屏总览使用栅格安排统计和公告。
- 老人、监护人、家属、手表信息和评论管理补齐加载、失败提示与重试。
- 总览说明数字统计口径，密码输入使用锁图标；未上报的数据不显示为正常。

## 二、建档和设备关系更可靠

- 支持先创建老人档案，再登记和绑定手表，不再要求先有手表阈值档案。
- 档案编辑不改写设备归属；跨老人改绑需要先解绑，事务维护设备与主设备引用。
- 重绑保留人工设置的阈值；移除主设备后，如仍有其他绑定设备，保留其中编号最小的设备。
- 修正喜好食物、忌口、常用药字段错位；监护人选择读取完整分页，失败时可重试。
- 缺失心率、血压或睡眠保留 NULL，避免生成 0 值及虚假正常状态。

## 三、照护任务形成闭环

- 总览正式挂载照护组件，支持 SOS 接单、开始处置、登记措施、另一名主管独立复核。
- 按现有主管、护理员、审计员岗位显示操作；处置人不能复核自己的任务。
- 任务、已复核记录和事件履历支持分页，避免只显示首批数据。
- 中文处置记录按字符计数；失败提示显示在弹窗内，保留已输入内容。
- 复核关闭同步清除该任务关联告警，并刷新总览数字，不会清除后来产生的其他告警。
- 服务心跳、通知网关和送达回执配置分别提示，不将进程正常当作通知送达。

## 四、MySQL 主库 + PostgreSQL 分析库

| 数据库 | 分工 |
| --- | --- |
| MySQL | 账号、档案、设备、健康原始记录、轨迹、告警、照护事务、审计、公告评论及持久化队列 |
| PostgreSQL | 健康、轨迹和照护的异步分析投影；健康日统计、照护状态汇总视图 |

- PG 断线时，核心业务继续使用 MySQL，分析事件保留；恢复后自动重连并补齐。
- 同步支持重复重放、删除墓碑及旧事件防复活，诊断展示 PG 状态、积压量和最近同步时间。
- 附独立双库 Compose 模板、旧 PG 到空 MySQL 的离线导入工具，以及分析投影回填工具。

## 升级前必读

1. **先备份旧数据库和图片。** 数据库服务与应用分开部署，安装包不包含 MySQL 或 PG。
2. **配置项已改变。** Go 使用 `MYSQL_DSN`、`PG_ANALYTICS_URL`；桌面使用 `SUINING_MYSQL_DSN`、`SUINING_PG_ANALYTICS_URL`。旧的 `SUINING_DATABASE_URL` 不再作为业务主库回退。
3. **旧数据不会因安装软件自动迁移。** 停止两端应用写入，先运行 `go run ./cmd/transfer-postgres` 预检查，再用 `--apply` 导入空 MySQL。目标非空时拒绝导入，失败时业务数据及分析事件一同回滚；图片另行复制。
4. **已有历史错误不批量改写。** 历史错误归属、错位字段和缺测 0 值需要核对后另行清理。
5. **没有默认管理员账号。** 空库初始化时创建；导入旧数据后沿用原账号。

完整步骤见 [双库配置与迁移说明](../DUAL_DATABASES.md)、[使用配置](../SETUP.md)。通知网关与长期值守要求见 [照护部署](../CARE_SERVICE_DEPLOYMENT.md)。

## 打包改进

- 统一产品元数据与前端、桌面、Cargo 锁文件版本，校验脚本同时检查锁文件内的产品版本。
- 构建脚本正确识别 `CARGO_TARGET_DIR`，支持隔离构建目录中的签名目标与安装包定位。

## 远程 preview 健康采样整合

保留远程健康批量采样、版本修订、增量游标、绑定版本与统计功能，并适配 MySQL 主库；新增 MySQL 健康迁移及旧 PG 的兼容迁移。离线导入支持 0006／0007／0008，保留健康记录与游标。详细验证与源码、安装包的区别见 [整合记录](../INTEGRATION_2.0.6.md)。此前本地安装包未包含此次整合，不作为当前源码的对应二进制；本次不发布 Release。

本地构建不等于生产上线。真实手表、短信网关、生产数据迁移、长期负载和现场救援流程未在本轮验收。Windows 安装版在缺失 WebView2 时需要联网补装；免安装版需要系统已有 WebView2。
