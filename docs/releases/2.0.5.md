# 岁宁 2.0.5 · 值守可靠性、岗位权限与隐私审计（源码预览）

2.0.5 基于 2.0.4 的求助事件闭环和独立部署方案，继续补强**通知服务故障发现、任务优先工作台、职责划分与敏感数据访问留痕**。本版本发布源码，不是经过实地认证的医疗或紧急救助系统。

## 本次主要变化

- **通知可靠性**：常驻 Go 通知工作进程向数据库写入心跳；主管可查看工作进程健康状态、待发送/失败/中断任务、超时事件及最早待发送时间；工作进程中断时在工作台突出提醒。持久化重试、崩溃恢复、请求幂等和独立 systemd 服务由 2.0.4 继承。
- **回执竞态修复**：可信网关签名确认可能在 webhook 请求尚处于 `sending` 时先到达；现在能够正确入账送达回执，不会误判为提前回执，重复回执仍拒绝。
- **任务驱动的首页**：保持原绿色视觉，任务列表明确长者、接单人、通知进度、处理期限、超时标记及**下一步照护动作**，提供服务健康诊断。
- **岗位权限**：主管可设定护理员、审计员；护理员可接单/处置但不能复核关闭，审计员只读照护任务。既有 ADMIN 未分配岗位时仍兼容为主管，部署前必须完成账号清理。
- **敏感操作审计**：记录照护履历查看、岗位调整，以及认证用户访问老人、健康、位置、设备和家属等接口的访问路径与身份；审计失败时拒绝披露敏感内容。日志不保存请求正文、坐标值和联系电话。
- **运维交付**：新增常驻服务 HTTP/数据库健康探测脚本，以及弱网重传、网关故障、服务恢复、人工接班、隐私权限和备份恢复验收门槛。

## 重要限制

- 岗位细化目前主要保护**照护管理接口**，其余旧 ADMIN 接口尚不是完整的岗位权限体系；**不包含多机构隔离**。
- 监控心跳正常不代表 SOS 已送达、不代表值班人员接手、更不能保证老人获救。
- 仓库自动测试不等于真实手表、短信运营商、网关回执、机构轮班、供电和网络故障演练都通过。
- **只提供源码 ZIP**，不含 Windows 安装包、Linux 预编译程序、托管云服务或真实短信网关。实际部署需要独立 PostgreSQL 和运行环境。
