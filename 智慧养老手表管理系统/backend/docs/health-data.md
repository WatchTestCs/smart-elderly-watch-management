# 健康采样接口与数据一致性

本文说明当前 Go 后端的健康采样写入、增量变更读取、统计查询与时间窗口语义。MySQL 保存业务采样及修订记录；设备归属通过绑定版本约束，读取游标按长者隔离。具体字段以 Go DTO、路由和 OpenAPI 契约为准。

## 接口

所有接口使用现有响应包络。设备接口以设备密钥认证；浏览器接口需要 ADMIN/FAMILY 会话及 CSRF，FAMILY 仅可访问关联老人。

### POST /api/v1/device/healthBatch

```json
{
  "deviceNo": "WATCH001",
  "secret": "<设备密钥>",
  "bindingVersion": 1,
  "samples": [{
    "recordId": "measurement-1",
    "source": "watch",
    "sourceDevice": "WATCH001",
    "metric": "heart_rate",
    "unit": "count/min",
    "value": 72,
    "start": "2026-11-02T09:00:00+08:00",
    "end": "2026-11-02T09:00:00+08:00",
    "semantics": "instant",
    "version": 1
  }]
}
```

每批 1–200 条，全部成功才提交。`sourceDevice` 必须等于认证设备编号。设备登录、心跳返回当前 `bindingVersion`；绑定变化后旧版本提交返回 409。客户端应保留采集时的绑定版本，不得把旧缓存改成新版本重传。

记录身份包含老人、认证设备、绑定版本、来源、来源设备、记录编号及指标。同版本相同内容重试去重；同版本不同内容返回 409 并回滚整批；较旧版本忽略；较新版本写入修订；`deleted: true` 为删除标记，仍须提供有效身份、时间和语义。缺测值不能当作零值。

支持心率、收缩压/舒张压、旧单值血压、血氧、体温、体重、步数、睡眠时长及睡眠阶段。瞬时采样起止时刻相同；步数必须明确 `interval` 或 `daily_total`；区间具有正时长。支持华氏温度、磅、小时及比例血氧转换为标准单位。

返回 `accepted`、`duplicates`、`writeRevision`；最后一个字段仅为写入回执，不能替代读取游标。

### POST /api/v1/health/changes

请求：`{"oldId":1,"after":0,"limit":100}`。返回记录及 `nextCursor`、`hasMore`。limit 默认 100、最大 200。读取包含删除修订。游标属于请求的 `oldId`，按该老人的 `nextCursor` 继续翻页，空页保留原游标；不得跨老人复用游标，也不得用 `writeRevision` 替代读取游标。`after` 和返回修订号不超过 JSON 客户端可精确表示的整数上限 9007199254740991。

MySQL 的 `mysql/0007_cluster_scheduling.sql` 引入按老人锁定的修订时钟。同一老人的写入持锁至事务提交，保证该老人的修订次序与提交次序一致，避免增量读取跳过尚未提交的修订。不同老人可以并行提交，修订号不代表跨老人的提交次序。各老人从全局高水位预留独占号段，修订号仍保持全局唯一；预留、切换号段等操作可以留下空洞，客户端只能使用返回的 `nextCursor`，不能自行按数量推算游标。旧 PG 路径仍使用原全局时钟。升级或回滚须先停止所有旧版写入，不能混用两种写入程序。

### POST /api/v1/health/statistics

统计查询中的微秒字段用于筛选候选采样，最终按原始 RFC3339 时间精确判断 `[from,to)`：瞬时采样包含起点、不含终点，区间必须与窗口相交。候选范围向外包含边界，再剔除窗口外记录，避免不足 1 微秒的采样或跨日尾段漏算。查询容量限制按候选记录数执行，超限明确报错，不返回被截断的统计。

请求需明确 `oldId`、`source`、`sourceDevice`、`metric`、`semantics`、RFC3339 `from`/`to`。范围左闭右开，最长 366 天；超过 10000 条要求缩短范围。日累计必须使用相同 UTC 偏移的完整自然日；睡眠区间取并集，重叠步数区间拒绝合计，来源与语义不混合。

## 跨窗口步数与夜间累计计数

`steps/interval` 跨越统计窗口时按持续时间比例估计，保留整数计数。对每条原始区间，在窗口两端分别计算累计分配量并取差；累计量采用半步向上取整，因此相邻不重叠窗口的分配量可加，不会因各窗口独立取整重复或丢失步数。此分配假定活动在原区间内均匀，不能恢复真实步行时间。`count` 为与窗口相交的区间数，`min/max` 为这些区间在窗口内的分配计数；完整落入窗口的记录保持原结果。原区间重叠仍报错。

区间计数与合计最多为9007199254740991，确保JSON/float64精确表示整数；超出范围报错。持续时间必须为正且可用Go的time.Duration精确表示，超出约292年的区间拒绝计算。忽略缺失值、对未知时区报错及daily_total按报告日选取最后快照、同时间冲突拒绝的契约保持不变。

日累计同时间冲突在全部有效采样中检查，不依赖写入顺序或较晚快照；相同瞬间的不同 UTC 偏移表达仍视为同一时刻。有限非负瞬时值求和溢出时，通过缩放计算可表示的平均值。日算法版本为 2，版本参与日缓存身份，旧版本日结果不会直接用于新请求。

夜间`daily_total`按计数日界识别午夜清零，即使新日累计高于前一日最后样本，也累计新日值。设备可在每条样本的现有`metadata`中声明`"counterTimezone":"Asia/Shanghai"`等IANA时区；它独立于告警规则时区。未声明时，计数日按`start`的RFC3339 UTC偏移解释，同一窗口内偏移必须一致。设备以UTC传输但按本地午夜清零时，适配器须声明计数时区；采用夏令时的设备也应显式提供IANA时区。未知计数时区、时区声明变化、时间倒序、同时间冲突和同日不明回退均不产生有效活动量。

没有可信重启标记时，不将同日回退推断为低电量重启。重置前最后样本至午夜之间未观察到的步数无法还原；夜间活动增量是可观测下界，不能保证恢复全部实际活动。区间步数的夜间窗口使用同一分配规则，继续遵守夜间样本筛选与重叠拒绝规则。

动态基线偏离容差为百分比门限、标准差倍数和绝对下限三者最大值：心率8 bpm、收缩压12 mmHg；恰好等于容差不触发。固定心率/收缩压上下限继续独立运行。这是告警算法约定，不构成临床诊断或硬件准确性证明。

## 兼容性与限制

设备通过 `POST /api/v1/device/healthBatch` 提交采样，写入必须携带采集时取得的 `bindingVersion`。家属端当前通过 `POST /api/v1/health/latest` 读取最新采样；增量变更和统计接口分别用于游标同步与时间窗口聚合，不能将写入回执 `writeRevision` 当作读取游标。

健康采样数据保存在 MySQL 业务库。PostgreSQL 是可选分析投影，不能把它视为健康采样原始记录的替代主库。数据库继续独立部署；迁移需要相应 DDL 权限。修订记录目前没有自动清理策略；按老人锁及全局独占号段保证游标一致性，吞吐量须以实际持久化和集群测量结果为准。

## 验证边界

在后端目录执行 `go test ./...` 与 `go vet ./...`。需要真实数据库验证时，必须配置独立的 MySQL/PG 测试实例和专用测试库；未配置的数据库用例会跳过，不能将跳过视为集成测试通过。当前提交的自动化结果以对应 commit 的 GitHub Actions 为准。

协议测试和模拟数据不能替代真实设备、传感器、生产数据迁移或通知网关验收。健康指标缺失不得填零；统计算法输出不构成临床诊断或设备准确性证明。
