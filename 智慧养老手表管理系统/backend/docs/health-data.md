## 接口

所有接口使用现有响应包络。设备接口以设备密钥认证；浏览器接口需要 ADMIN/FAMILY 会话及 CSRF，FAMILY 仅可访问关联老人。

### POST /restful/device/healthBatch

```json
{
  "deviceNo": "WATCH001",
  "secret": "<设备密钥>",
  "bindingVersion": 1,
  "samples": [{
    "recordId": "measurement-1",
    "source": "watch",
    "sourceDevice": "WATCH001",
    "metric": "heart_rate",
    "unit": "count/min",
    "value": 72,
    "start": "2026-10-19T09:00:00+08:00",
    "end": "2026-10-19T09:00:00+08:00",
    "semantics": "instant",
    "version": 1
  }]
}
```

每批 1–200 条、请求最多 2 MiB，全部成功才提交。`sourceDevice` 必须等于认证设备编号。设备登录、心跳返回当前 `bindingVersion`；绑定变化后旧版本提交返回 409。客户端应保留采集时的绑定版本，不得把旧缓存改成新版本重传。

记录身份包含老人、认证设备、绑定版本、来源、来源设备、记录编号及指标。同版本相同内容重试去重；同版本不同内容返回 409 并回滚整批；较旧版本忽略；较新版本写入修订；`deleted: true` 为删除标记，仍须提供有效身份、时间和语义。缺测值不能当作零值。

支持心率、收缩压/舒张压、旧单值血压、血氧、体温、体重、步数、睡眠时长及睡眠阶段。瞬时采样起止时刻相同；步数必须明确 `interval` 或 `daily_total`；区间具有正时长。支持华氏温度、磅、小时及比例血氧转换为标准单位。

返回 `accepted`、`duplicates`、`writeRevision`；最后一个字段仅为写入回执，不能替代读取游标。

### POST /restful/health/changes

请求：`{"oldId":1,"after":0,"limit":100}`。返回记录及 `nextCursor`、`hasMore`。limit 默认 100、最大 200。按返回的 nextCursor 继续翻页；空页保留原游标。读取包含删除修订。全局修订时钟在事务提交前串行化写入，避免跳过尚未提交的较早修订。

### POST /restful/health/statistics

请求需明确 `oldId`、`source`、`sourceDevice`、`metric`、`semantics`、RFC3339 `from`/`to`。范围左闭右开，最长 366 天；超过 10000 条要求缩短范围。日累计必须使用相同 UTC 偏移的完整自然日；睡眠区间取并集，重叠步数区间拒绝合计，来源与语义不混合。

## 兼容性与限制

旧上报与界面继续沿用现有路径；没有把历史日报转换成采样，也没有让旧前端自动读取新接口。旧上报接口没有新增绑定版本约束，不应把新接口的隔离保证扩大到旧路径。Apple 导入和 alertEvents 接口未启用。

数据库继续独立部署；离线启动和现有连接策略保持不变。启动迁移需具备创建表、函数及触发器权限。新增表保留修订记录，目前没有自动清理策略；全局时钟优先保证游标一致性，未经吞吐量测量，不宣称高并发性能提升。

## 审查与验证

**Standards：** 原包存在覆盖新架构及鉴权前获取全局写锁的问题。采用增量适配，保留现有模块；新路径先鉴权再锁设备，未修改全局 hwAuth 的锁行为。

**Spec：** 原包瞬时采样时间约束不完整，已补齐并添加回归；Apple 关联记录修订冲突暂缓处理，相关未完成能力没有作为已上线功能合入。

在 Windows Go 1.27.2、隔离 PostgreSQL 16 下执行后端 `go test ./...` 通过，包括现有照护/权限测试，以及新增的版本冲突、原子回滚、家属隔离、提交顺序游标、绑定版本、统计和 CSRF 测试。无生产数据库操作；未运行桌面打包、硬件联调或远程 CI。
