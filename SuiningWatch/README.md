# 岁宁守护 · HUAWEI WATCH 5 穿戴端工程

本目录是岁宁配套的 HarmonyOS 原生穿戴端应用，基于 ArkTS、ArkUI 与 Stage 模型开发，目标设备为 HUAWEI WATCH 5。当前版本专用于 DevEco Studio 穿戴模拟器与后端的协议联调：所有心率与步数均为页面显式标注的模拟数据，未接入真实硬件传感器，也不包含跌倒检测或医疗诊断功能。

## 主要功能

- 适配圆形表盘的深色界面，包含“首页”、“记录”、“设置”三个标签页，支持滚动访问各项操作。
- 支持设备密钥认证、通过后台生成的设备绑定码关联长者，以及发送设备心跳。
- 手动生成模拟心率与步数，通过 `healthBatch` 接口批量上报。
- 本机最多缓存 200 条待上传的模拟采样，每条采样带有固定记录 ID 供服务端幂等去重。上传前会校验服务器地址、设备号、长者 ID 与绑定版本号（`bindingVersion`）；若长者绑定关系已发生变更，客户端会拒绝补传旧批次数据。
- SOS 求助具备二次确认弹窗。在未收到明确响应前重试同一次求助会复用相同的 `requestId`，避免服务端重复建单，并在表盘上明确区分“后台已接收”与“通知已送达”状态。
- 应用私有 `Preferences` 仅持久化后端地址、设备号、待上传模拟采样与未确认的求助请求。设备密钥仅驻留在内存中，应用重启后需重新输入。

## 开发环境要求

本工程已在 DevEco Studio 6.1.1.280（内置 SDK 6.1.1 API 24、兼容目标 HarmonyOS 5.1 API 18）与 Node.js 18 环境下完成编译，并在 API 24 Wearable 模拟器中完成命令行安装与启动；这些历史记录不代表当前分支完整原生验收通过。请在 DevEco Studio 中选择 `Open`，直接打开仓库根目录下的 `SuiningWatch` 文件夹（切勿仅打开子目录 `entry`）。

## 构建与模拟器运行

在 PowerShell 7 中执行构建脚本：

```powershell
cd '<仓库目录>\SuiningWatch'
./scripts/build.ps1
```

该脚本直接调用 DevEco Studio 自带的构建工具链（若 IDE 安装在非默认路径，可通过 `-DevEcoHome` 参数指定）。构建完成后会生成未签名的调试包 `entry/build/default/outputs/default/entry-default-unsigned.hap`；如需安装至物理手表真机，需先配置个人或企业开发者签名证书。

在 DevEco Studio 的 Device Manager 中启动 Wearable 模拟器后，运行以下命令安装并启动应用：

```powershell
./scripts/run-emulator.ps1 -Target '127.0.0.1:5555' -BackendPort 8796
```

启动脚本会通过 HDC 将模拟器内的 `127.0.0.1:18796` 端口转发至宿主机的 `127.0.0.1:8796`，无需将本机后端或数据库暴露到局域网。

## 与管理后台联调步骤

1. 启动 Go 后端服务（监听 `8796` 端口），访问 `http://127.0.0.1:8796/api/v1/service/status` 确认 `databaseReady` 为 `true`。
2. 在管理端网页创建一名测试长者档案，随后在“设备管理”中登记一块模拟手表，并妥善保存创建时仅展示一次的设备密钥。
3. 在手表端打开“设置”页，填入后端地址 `http://127.0.0.1:18796`、设备号以及刚才保存的设备密钥（注意区分设备密钥与后台管理员密码）。
4. 点击“保存地址并认证”，认证通过后输入后台生成的设备绑定码（注意不要误填家属注册用的邀请码）完成长者关联。
5. 回到手表“首页”点击“生成模拟采样”，再进入“记录”页点击“上传记录”，随后在管理端健康采样链路核对上报结果；旧版兼容的心率血压列表未必展示相同记录。
6. 点击“SOS 模拟求助”并确认发送，管理端运营总览将生成对应的紧急照护工单。若后端已挂载真实通知网关，此操作会触发外部通知，请仅在隔离测试环境中执行。

## 协议测试

```powershell
npm ci
npm test
```

单元测试基于 `package-lock.json` 固定的 TypeScript 5.9.3 直接转译生产代码 `Protocol.ets`，可在无 DevEco Studio 的环境下独立验证绑定版本隔离、重试 ID 幂等、采样格式与队列上限。

如需针对真实后端运行端到端协议联调脚本 `tests/backend.e2e.cjs`，请先准备全新空库的独立测试后端实例，并设置环境变量 `WATCH_TEST_URL`（仅限本机 HTTP 地址）与 `WATCH_TEST_SETUP_TOKEN`。详细的集成验收记录见 [手表端同分支整合说明](../docs/WATCH_INTEGRATION.md)。

## 当前已知限制

- 采用手动触发采样与手动上传机制，暂未实现后台定时采集与自动静默上传，以便在联调时精确控制写入时机。
- 仅用于协议与流程联调，尚未接入真实生理传感器、GPS 定位模块、睡眠阶段检测及本地敏感数据加密存储。
- 应用重启但尚未重新输入设备密钥认证前，仅支持查看本地状态，无法生成带有效归属的新采样。

- 后台接收 SOS 不代表外部通知已送达或人员已到场，仍需人工跟进与独立复核。
- Node 协议测试仅转译生产 `Protocol.ets`，不能代替 DevEco 原生编译、模拟器交互或真机验证。WATCH 5 真机安装、签名、传感器权限与圆屏视觉验收仍未完成。
